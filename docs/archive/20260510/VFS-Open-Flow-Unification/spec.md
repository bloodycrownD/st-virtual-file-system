# VFS-Open-Flow-Unification 需求说明

## 背景

当前 VFS 文件管理交互存在以下割裂点：

1. 目录进入依赖双击，不符合常见文件管理器中“目录单击进入”的直觉。
2. 文件 row 菜单中存在“查看/编辑”并行入口，语义分裂，且与文件双击行为不统一。
3. 文件打开后的模式入口不够统一，用户希望“打开”作为唯一主入口，并默认进入预览。

为提升可理解性与操作效率，需要统一文件/目录“打开”交互，并精简 row 菜单动作语义。

## 目标

- 统一“打开”语义，降低用户在“查看 vs 编辑”之间的选择成本。
- 提升目录导航效率：目录支持单击进入。
- 文件进入编辑器时默认处于预览模式，符合“先看后改”的流程。
- 保持 chat/template 双 scope 与桌面/移动端交互一致。

## 范围

### 包含范围

- `chat + template` 两个 scope 的文件管理列表交互。
- 目录项单击进入目录。
- row 菜单新增/保留“打开”动作，并用于目录打开。
- 文件一次双击（标准 `dblclick`）进入编辑器模式，且默认预览模式。
- row 菜单去除“查看/编辑”，合并为“打开”；其他动作保留（如重命名/删除/切换状态等）。
- 自动化测试与 build 验证更新。

### 不包含范围

- VFS 核心存储、快照序列化、提交/回滚机制重构。
- 全局头部菜单（global-create）的信息架构调整。
- 非文件管理列表的其它入口（如历史页、日志页）交互重设计。

## 功能需求

### FR-1 目录单击进入

- 用户单击目录行（row 主体）即可进入该目录。
- 进入目录后路径与列表内容即时更新，行为与当前目录打开逻辑一致。

### FR-2 row 菜单“打开”动作

- 每个 row 菜单包含“打开”动作。
- 对目录点击“打开”时，行为与目录单击一致（进入目录）。
- 对文件点击“打开”时，执行文件打开流程（见 FR-3）。

### FR-3 文件双击打开与默认预览

- 文件一次双击（标准 `dblclick`）进入编辑器模式。
- 进入编辑器后默认处于“预览模式”（而不是源码编辑模式）。

### FR-4 去除“查看/编辑”并合并为“打开”

- row 菜单移除“查看”“编辑”两个动作。
- 保留“打开”作为统一入口，避免并行语义冲突。
- row 菜单中其余非本次目标动作维持原有行为。

### FR-5 跨端与跨 scope 一致

- desktop/mobile 在上述交互上的行为一致。
- chat/template 两个 scope 行为一致（若存在受限场景需明确错误提示，不可静默失败）。

## 非功能需求

- **一致性**：按钮文案与图标语义统一到“打开”，避免同层级重复入口。
- **可维护性**：动作映射逻辑集中管理，避免文件/目录分支散落导致回归。
- **可测试性**：关键交互需有自动化用例覆盖（目录单击、文件双击、菜单动作合并）。
- **兼容性**：不破坏现有 row/header action menu 的稳定开关与 outside dismiss 行为。

## 验收标准

| AC | 描述 |
|---|---|
| AC-1 | 目录单击即可进入目标目录，路径与列表内容正确刷新。 |
| AC-2 | row 菜单可见“打开”动作，且目录执行“打开”时行为等同单击进入。 |
| AC-3 | 文件一次双击进入编辑器，默认展示预览模式。 |
| AC-4 | row 菜单不再出现“查看/编辑”动作，仅保留“打开”统一入口（其他动作不受影响）。 |
| AC-5 | desktop/mobile 与 chat/template 行为一致。 |
| AC-6 | `npm run build` 与自动化测试通过。 |

## 风险与待确认项

- “目录单击进入”与“row 尾部菜单点击”可能存在事件冒泡冲突，需要确保点击菜单区域不会误触目录打开。
- 文件默认预览模式需与现有 `editorPreviewMode` 生命周期对齐，避免从其它入口返回时状态残留。
- 菜单动作文案从“查看/编辑”收敛到“打开”后，需要同步测试断言与可访问性标签。
