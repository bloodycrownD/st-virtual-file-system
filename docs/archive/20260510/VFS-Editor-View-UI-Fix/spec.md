# VFS-Editor-View-UI-Fix 需求说明

## 背景

模板管理 / 聊天侧虚拟文件系统在 **查看（reader）** 与 **编辑（editor）** 阶段存在明显 UI 问题：

1. **工具栏按钮**（如 `EditorScreen` 内 Preview / Save）使用宿主不统一的亮色块样式，与当前 VFS 深色面板、圆角描边、`menu_button` / 图标化工具栏语言不一致。
2. 上述按钮为 **纯英文文案**（Preview / Save / Saving…），与产品其余中文语境不一致，且用户要求 **一律使用图标**（必要时保留 `aria-label` / `title`）。
3. **布局分裂**：`VfsMainScreen.vue` 在桌面宽屏进入预览/编辑时使用 `vfs-desktop-grid`（左侧文件树 + 右侧内容）；移动端使用 `vfs-mobile-stack`（单列全宽内容区 + 顶部 Back）。用户希望 **桌面端与移动端统一为移动端这种「预览/编辑阶段占满弹窗内容区、不并排文件树」的全屏栈效果**（以当前 `layoutMode === 'mobile'` 分支的交互与占比为基准对齐桌面端）。
4. **缺少退出入口**：移动端在 `vfs-mobile-content` 顶部有 `Back` 按钮（`requestModeChange('list')`），但 **查看模式** 与 **桌面端** 整体缺少与用户心智一致的 **「退出查看/编辑」** 图标按钮；需在 **两种断点** 上均提供清晰可见的退出控件。

另：用户确认退出时若存在未保存编辑内容，应采用 **确认对话框**（保存 / 放弃 / 取消），而非静默丢弃。

## 目标

- 查看/编辑阶段工具栏 **视觉与 SillyTavern/VFS 现有控件一致**，无明显「白底突兀按钮」。
- Preview / Save 等与阶段相关的 **主操作改为图标化**（Saving 等进行中状态可用图标 + `aria-busy` 或禁用 + 旋转图标等，具体由设计实现）。
- **桌面与移动** 在 reader/editor（及若适用时同壳内的其它全屏阶段）采用 **同一套全屏栈布局**，不再在桌面预览/编辑时出现左侧文件树分栏。
- **显式退出** 查看/编辑（回到文件列表阶段），且 **未保存时确认**。

## 范围

### 包含范围

- `src/app/screens/business-screens/VfsMainScreen.vue`：预览/编辑阶段 **布局分支** 收敛（桌面不再走 `vfs-desktop-grid` 分栏，与移动 `vfs-mobile-stack` 对齐或共用同一结构）。
- `src/app/screens/pure-screens/EditorScreen.vue`：工具栏按钮 **样式与图标化**；与预览切换、保存触发行为不变。
- **退出控件**：在 reader + editor（及实现时与同一全屏壳共享顶栏的阶段，如仅 reader 无内嵌工具栏时由父级提供顶栏）统一提供 **图标退出**，文案/可访问性补充中文 `title` / `aria-label`。
- **未保存确认**：在退出或返回列表路径上接入确认流（可复用现有 `isDirty` / 保存管线；取消则留在当前模式）。
- **范围表面**：`scope: 'chat' | 'template'` 下 **files 页签** 内预览/编辑相关 UI（含模板管理弹窗场景）。
- **回归测试**：更新或新增 Vitest / Vue Test Utils 用例（布局 `data-testid`、保存按钮 testid、退出确认交互若可测）。

### 不包含范围

- 修改 VFS 核心读写、快照序列化、模板覆盖业务规则。
- 重做文件管理器列表阶段（`list-only-layout`）信息架构。
- 幻灯片（slideshow）模式的完整交互重设计；若当前与 reader/editor 共用同一顶壳，**仅**保证退出/图标语言一致时可顺带对齐，不强制扩展 scope。
- 历史记录 Tab、日志 Tab 的独立 UI。

## 功能需求

### FR-1 工具栏视觉一致

- Preview / Source 切换、Save（及进行中态）等 **主按钮** 使用与 VFS 文件管理器工具栏一致的 **暗色、描边或 `menu_button` 系** 风格，禁止默认浏览器或高对比白底主按钮样式。
- 按钮尺寸与触控目标与现有 `vfs-fm-icon-button` / `menu_button` 密度 **协调**（具体 class 以实现对照现有扩展为准）。

### FR-2 图标化主操作

- Preview ↔ Source（或等价预览切换）与 Save **以图标呈现**，不显示英文单词作为主标签；**Saving…** 不以纯英文长文案为主 UI（可用图标状态 + 无障碍文本）。
- 每个图标控件具备 **`aria-label` 与 `title`（中文）**，满足键盘与读屏。

### FR-3 布局统一（桌面 = 移动全屏栈）

- 当 `mode` 为 `reader` 或 `editor`（以及实现中与该壳一致的阶段）时，**无论 `layoutMode` 为 desktop 或 mobile**，均采用与 **当前移动端** 相同的 **单列全宽内容区** 结构：不显示 `vfs-desktop-grid` 左侧 `aside` 文件树分栏。
- 返回列表后，文件列表阶段布局 **维持** 现有列表专用布局（`vfs-list-only-layout` 等），不受本需求改为分栏预览。

### FR-4 退出查看/编辑

- 在 **桌面端与移动端** 的查看/编辑全屏阶段，提供 **同一位置的退出控件**（建议顶栏左侧或顶栏统一工具区），图标表达「返回列表 / 关闭预览」；点击效果为 **回到 `list` 阶段**（`requestModeChange('list')` 或等价）。
- **Reader** 无内嵌工具栏时，由 **父级布局**（`VfsMainScreen` 或抽取的壳组件）提供与 Editor 一致的顶栏退出，避免仅移动端有 Back、桌面无入口。

### FR-5 未保存确认

- 在 **退出** 或 **返回列表** 时，若 `editor` 且 `isDirty === true`，**不得**直接丢弃；弹出确认：**保存 / 放弃更改 / 取消**。
  - **保存**：走现有保存流程，成功后回到列表（或成功后仍停留由产品惯例决定，默认成功后回列表）。
  - **放弃**：丢弃未保存修改并回列表。
  - **取消**：关闭对话框，留在编辑态。

## 非功能需求

- **可访问性**：图标按钮具备 `aria-label`；进行中状态可 `aria-busy` 或 `disabled` 说明。
- **一致性**：与 `fa-solid` / 扩展内已有图标选用习惯一致（与 `VfsFileManagerPanel` 等对齐）。
- **性能**：不增加明显重渲染；布局分支合并后避免重复挂载大组件。

## 验收标准

| AC | 描述 |
|----|------|
| **AC-1** | 模板管理弹窗中进入编辑：Preview / Save **为图标**，样式与 VFS 深色工具栏 **协调**，无截图中大面积白底主按钮。 |
| **AC-2** | 浏览器宽度 ≥1024（desktop）与 <1024（mobile）下，进入 **查看/编辑** 均为 **单列全宽**，**无** 左侧文件树分栏。 |
| **AC-3** | 桌面与移动在查看/编辑阶段均有 **图标退出**，返回文件列表；Reader 阶段同样有退出，不单依赖弹窗右上角关对话框。 |
| **AC-4** | 编辑有未保存修改时点击退出：**出现** 保存/放弃/取消确认；**取消** 留在编辑；**放弃** 回列表且内容不写入磁盘。 |
| **AC-5** | `npm run test:run` 与 `npm run build` 通过；关键交互有自动化覆盖或更新既有用例。 |

## 风险与待确认项

- **幻灯片模式**：若与 reader/editor 共用布局壳，退出行为是否一并统一 —— 建议在实现时 **最小对齐**（同一顶栏退出语义），否则在代码注释中注明例外。
- **保存失败**：确认对话框「保存」若失败，应 **保留在编辑态** 并沿用现有 toast/错误提示。
- **国际化**：当前宿主以中文为主；若后续 i18n，图标仍保留，`title` 走词条即可。
