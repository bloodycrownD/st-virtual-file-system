# popup-height-and-scroll-fix 需求说明

## 背景

当前 VFS 弹窗在新布局下出现两个明显问题：

- 弹窗视觉高度偏短，主操作区被压缩，整体观感突兀。
- 点击“更多操作”后出现不合理的纵向滚动（主弹窗/内容区被挤压），与操作数量不匹配。

用户预期是：弹窗高度应稳定且足够高；“更多操作”应作为浮层覆盖显示，不应把主弹窗挤出滚动。

## 目标

- 将 VFS 弹窗高度策略调整为**固定更高**（目标 `70vh`）。
- “更多操作”菜单使用覆盖式浮层（overlay）展示，不参与主布局高度计算。
- 展开“更多操作”时不触发弹窗主体纵向滚动。

## 范围

### 包含范围

- 调整 `#st-vfs-popup` 容器高度策略（固定 70vh，保留视口边界保护）。
- 调整文件管理区滚动分层：
  - 头部（路径/按钮/更多操作）固定可见
  - 列表区独立滚动（如需要）
- 调整“更多操作”浮层渲染策略（overlay，不挤压主内容）。

### 不包含范围

- 不改动“更多操作”业务动作本身（create/view/edit 等）。
- 不改动 reader/editor/slideshow 的业务逻辑。

## 功能需求

### FR-1 弹窗高度固定更高

- VFS 弹窗默认高度为 `70vh`（可设 `max-height` 保护，避免超出视口）。
- 弹窗打开后高度稳定，不因“更多操作”展开发生突兀变化。

### FR-2 更多操作覆盖展示

- “更多操作”菜单必须以浮层方式展示（overlay）。
- 菜单展开不应推动/挤压主内容，不应改变弹窗主容器高度。

### FR-3 滚动行为控制

- 展开“更多操作”时，不触发弹窗主体纵向滚动。
- 如内容过多，优先由局部区域（如文件列表）承担滚动，而非弹窗整体抖动。

## 非功能需求

- **视觉稳定性**：弹窗尺寸在常见操作（展开/收起更多操作）下保持稳定。
- **交互一致性**：菜单展开方向与层级清晰，不被容器裁切。
- **可维护性**：滚动与层级规则通过明确 class 管理，避免后续样式互相覆盖。

## 验收标准

- **AC-1 高度稳定**：弹窗打开后为固定较高高度（约 70vh），不会显著偏短。
- **AC-2 无离谱滚动**：点击“更多操作”后，不出现主弹窗纵向滚动条突现/跳动。
- **AC-3 菜单可见完整**：更多操作菜单以浮层显示，不被裁切，操作项可点。
- **AC-4 体验一致**：多次展开/收起“更多操作”时，布局不抖动，视觉一致。

## 风险与待确认项

- 若某些主题对 `dialog`/`details` 有强覆盖，可能影响浮层层级；需在 `#st-vfs-popup` 作用域内提升 z-index 并控制 overflow。
