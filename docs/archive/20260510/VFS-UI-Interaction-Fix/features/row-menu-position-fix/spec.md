# row-menu-position-fix 需求说明

## 背景

在 `split-action-menus` 引入“每行三点菜单”后，出现了交互缺陷：

- 点击行末三点后，菜单浮层位置偏移，可能贴到错误位置或错误行。
- 打开菜单会导致列表/弹窗产生不期望滚动变化（跳动或新增滚动感）。
- 某些情况下菜单会受列表容器裁切，影响可见与可操作性。

这与预期“像 header 三点一样以 overlay 展示、且不影响布局滚动”的行为不一致。

## 目标

- 将行末三点菜单调整为稳定 overlay 浮层，定位锚定当前点击按钮。
- 打开/关闭菜单时不改变父级滚动位置，不触发主弹窗额外滚动变化。
- 保证 chat/template、desktop/mobile 下位置表现一致可用。

## 范围

### 包含范围

- 文件管理列表行内三点菜单（row action menu）的定位与弹层行为。
- 相关容器的 `position / overflow / z-index / transform` 协调。
- 作用界面：
  - 虚拟文件系统（chat）
  - 模板管理（template）
- 作用布局：
  - desktop
  - mobile

### 不包含范围

- 不调整菜单动作集合（动作内容与权限维持 `split-action-menus` 现状）。
- 不改动 header 三点菜单语义（仅可复用其 overlay 设计思路）。
- 不新增新的动作类型或业务逻辑。

## 功能需求

### FR-1 行菜单采用 overlay 机制

- 行末三点菜单必须以 overlay 浮层方式显示，不挤压、不重排列表行高度。
- 菜单层级应高于列表项内容，且不被行容器边界裁切。

### FR-2 锚点定位正确

- 菜单默认以“右下展开（overlay-right-bottom）”锚定当前点击的三点按钮。
- 同一时刻仅当前行菜单处于打开态时，位置必须紧邻对应按钮，不漂移到其它行。

### FR-3 不影响父滚动

- 打开/关闭行菜单不应改变父容器滚动位置（包括列表区域与弹窗主区域）。
- 菜单超长时，仅菜单自身滚动（若触发高度限制），不推动父布局滚动。

### FR-4 双端一致性

- 在 chat/template 两个界面表现一致。
- 在 desktop/mobile 两种布局下均保持锚点正确、无滚动跳动、可正常操作。

## 非功能需求

- **可访问性**：保留 `title` / `aria-label` 与键盘可聚焦基础行为。
- **视觉一致性**：样式与 header 三点菜单保持一致的按钮/面板基线。
- **可维护性**：定位和滚动约束尽量收敛在行菜单组件与其局部容器，避免全局 CSS 污染。

## 验收标准

- **AC-1 锚点正确**：点击任意行三点，菜单紧贴该按钮右下方出现，不错位到其他行。
- **AC-2 无父滚动扰动**：打开/关闭菜单时，列表和弹窗主区域滚动位置保持不变。
- **AC-3 不被裁切**：菜单不会被列表容器裁掉，可完整点击操作。
- **AC-4 双端稳定**：desktop/mobile、chat/template 四种场景均通过 AC-1~AC-3。
- **AC-5 回归覆盖**：新增/更新测试覆盖定位锚点与滚动不扰动的关键路径。

## 风险与待确认项

- 若菜单使用绝对定位，需谨慎处理外层 `overflow` 与 stacking context，避免在特定主题/CSS 下出现层级异常。
