# split-action-menus 需求说明

## 背景

当前文件管理面板中“更多操作”菜单同时承担了：

- **全局动作**（例如新建文件/新建目录）
- **条目动作**（查看/编辑/重命名/删除等，依赖当前选择）

这导致用户体验上出现不必要的绑定与困惑：

- 未选中条目时，菜单可能被禁用或缺少条目动作。
- 选中与否影响可用操作，造成“为什么点不了”的疑惑。
- 全局创建与条目动作混在一起，信息架构不清晰。

## 目标

- 将动作拆分为两个入口：
  - **Header 更多操作**：仅提供“新建目录 / 新建文件”（全局创建）
  - **每行条目更多操作**：提供该条目相关动作（查看/编辑/重命名/删除等）
- 条目动作不再依赖“全局选择状态”才能使用；通过行末按钮直达。
- 移动端友好（热区足够、避免误触），并保留 `title/aria-label` 语义。

## 范围

### 包含范围

- 文件管理面板 Header 区域：
  - 现有“更多操作”入口调整为**仅创建动作**
  - 创建动作：新建目录、新建文件
- 文件/目录列表项（每行）：
  - 新增行末“三点（kebab）”按钮作为条目动作入口
  - 点击行末更多时：**自动选中该条目**，并打开条目动作菜单
- 覆盖 scope / 布局：
  - chat / template 两个界面
  - desktop / mobile 两种布局

### 不包含范围

- 不新增新的业务动作（仅重分布现有动作到更合理入口）。
- 不改变现有动作的业务语义（例如删除确认、重命名流程、编辑/查看切换规则等）。
- 不引入右键菜单作为唯一入口（可作为未来增强，但不在本次）。

## 功能需求

### FR-1 Header 菜单只保留创建动作

- Header “更多操作”菜单中仅包含：
  - 新建目录
  - 新建文件
- Header 菜单不再因为“未选中条目”而禁用。

### FR-2 每行条目提供独立更多操作

- 文件/目录列表的每一行末尾提供一个三点按钮（kebab icon）。
- 该按钮打开该条目的动作菜单，动作集合（按条目类型）：
  - 文件：查看、编辑、重命名、删除、切换状态（如当前已有）
  - 目录：查看/进入（若存在）、幻灯片/阅读模式、重命名、删除、应用展示策略、切换状态（如当前已有）

### FR-3 行末更多操作自动选中条目

- 点击行末三点按钮时：
  - 自动将该条目设为选中态（以便与现有 UI 状态一致）
  - 打开动作菜单
- 自动选中不得导致目录跳转或模式意外切换（仅更新选中态）。

### FR-4 移动端可用性与无障碍

- 行末三点按钮点击热区满足移动端易点（避免 1x1 小图标）。
- 所有图标按钮必须具备：
  - `title`
  - `aria-label`
- 菜单可通过键盘聚焦/触发（最低限度与现有 `details/summary` 行为一致）。

## 非功能需求

- **一致性**：与现有按钮风格一致（优先复用 `menu_button` / 现有 VFS scoped 样式）。
- **可维护性**：条目动作菜单的“动作可用性（按 kind）”逻辑集中在一处，避免分散。
- **回归安全**：补回归测试覆盖关键路径（header 创建、row 动作、选中联动）。

## 验收标准

- **AC-1 Header 不再禁用**：未选中条目时，Header “更多操作”可打开，且仅显示“新建目录/新建文件”。
- **AC-2 Row 动作随行可用**：每一行都有三点按钮，点击可打开该条目的动作菜单，不依赖全局是否选中。
- **AC-3 自动选中**：点击行末三点按钮后，该行成为选中态，菜单正常打开。
- **AC-4 移动端友好**：移动端下三点按钮热区足够，不易误触；菜单可正常操作。
- **AC-5 a11y**：Header 与 Row 的图标按钮均具备 `title/aria-label`。
- **AC-6 回归测试**：新增/更新测试覆盖 AC-1~AC-3 的关键交互与最小行为矩阵。

## 风险与待确认项

- 行末按钮会增加列表行的横向空间占用；需要确保文件名区域仍可良好截断（ellipsis）且不挤压过度。
