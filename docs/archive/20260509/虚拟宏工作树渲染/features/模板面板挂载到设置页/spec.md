# 变更需求：模板面板挂载到设置页

## 变更背景

在“虚拟宏工作树渲染”主需求中，VFS 在 `chat` 与 `ext` 两个域都生效。其中：

- `chat` 域是当前会话实际运行态。
- `ext` 域是模板态，作为新 chat 初始化与手动覆盖的来源。

本次变更目标是降低模板管理复杂度：模板侧不涉及工具调用写入，因此不需要日志与版本管理；但模板文件系统仍需要具备 Tab1 的核心能力，并提供明确入口与覆盖流程。

## 变更动机

- 模板态仅有用户手动更改，不需要提交历史与日志追踪。
- 在设置页提供稳定入口，便于集中管理模板文件系统。
- 明确“新建 chat 初始化”和“现有 chat 覆盖”两条模板应用链路。

## 范围变化（相对主 spec）

## 新增

1. 在设置页（`src/App.vue`）新增“模板管理”入口。
2. 点击“模板管理”打开模板弹窗（文件系统视图）。
3. 模板弹窗仅提供 Tab1 能力（文件管理/浏览/编辑等 Tab1 核心能力）。
4. 新建 chat 时，使用 ext 模板初始化 chat VFS。
5. 在 chat 面板新增“模板覆盖当前目录”动作，允许以模板覆盖当前 chat 文件目录。

## 调整

- 模板弹窗不包含日志与版本管理相关 UI/能力（即不提供 Tab2/Tab3 对应能力）。

## 不包含

- 不新增模板侧日志、提交记录、回滚能力。
- 不改变主需求中宏渲染协议（`VIRTUAL_FILE_TREE` / `VIRTUAL_WORK_TREE`）的输出格式。

## 功能需求

1. **设置页入口**
   - 在 `src/App.vue` 中提供“模板管理”按钮/入口。
   - 入口点击后可打开模板弹窗。

2. **模板弹窗能力边界**
   - 模板弹窗仅保留 Tab1 所需能力（文件树操作、文件内容编辑与保存等）。
   - 不显示日志分页、自动刷新、提交记录、回滚按钮与其相关状态。

3. **新建 chat 初始化**
   - 当创建新 chat 时，若存在 ext 模板快照，则以模板初始化 chat VFS。
   - 若模板为空或不存在，回退到主需求定义的默认初始化路径（至少保证 chat 快照合法非 null）。

4. **模板覆盖当前目录**
   - chat 面板提供“模板覆盖当前目录”按钮。
   - 用户触发后需二次确认（提示不可恢复）。
   - 确认后用 ext 模板覆盖当前 chat 文件目录，并触发 chat 相关视图刷新。
   - 覆盖完成后清空当前 chat 的日志与版本管理数据，语义等同“重新初始化 chat 工作树”。

5. **一致性约束**
   - 覆盖后，chat 宏渲染读取到的 VFS 状态应与 UI 文件树一致。
   - 模板态与 chat 运行态数据隔离，覆盖动作为单向复制（ext -> chat）。

## 影响模块

- `src/App.vue`（设置页入口）
- 模板弹窗 Screen/Composable（文件系统 Tab1 视图复用或裁剪）
- chat 初始化流程（新 chat 套模板）
- chat 覆盖动作与确认交互
- VFS 模板服务/适配层（模板读取与复制）

## 验收标准

1. 在设置页点击“模板管理”可打开模板弹窗。
2. 模板弹窗具备 Tab1 核心能力，可完成模板文件系统管理。
3. 模板弹窗不展示日志与版本管理能力。
4. 新建 chat 时按模板初始化目录（模板存在时生效）。
5. chat 面板可执行“模板覆盖当前目录”。
6. 覆盖动作前存在二次确认，且确认文案明确不可恢复。
7. 覆盖完成后，chat 文件树与宏读取结果保持一致。
8. 覆盖完成后，chat 日志与版本管理数据被清空，不保留覆盖前历史。

## 风险与注意事项

- 覆盖动作若不做确认，容易造成用户误操作与数据丢失感知。
- 若模板/聊天快照拷贝非深拷贝，可能引发双向污染。
- 需要避免在“模板模式”误触发提交/日志相关事件监听。
- 若覆盖后未同步清空日志/版本历史，会造成“内容已重置但历史仍旧存在”的一致性错觉。
