# 虚拟文件系统 需求说明

## 背景

当前项目是一个 SillyTavern 插件，核心能力围绕数据库（SQL）进行数据存取与管理。  
为了支持更灵活的文本资产组织与 AI 工作流，需要新增一个“虚拟文件系统（VFS）”能力，用目录/文件模型承载文本内容，而非表结构模型。

## 目标

- 在插件内提供可持久化的虚拟文件系统能力，支持目录与文本文件管理。
- 同时支持 UI 操作与命令/API 调用，两者复用同一套核心能力层。
- 为 AI 提供可持续维护的“工作区”与状态文件能力（核心业务价值）。

## 范围

### 包含范围

- 提供双命名空间 VFS：
  - 全局命名空间（Global）
  - Chat 私有命名空间（Per-Chat）
- 命名空间策略为严格隔离：
  - Global 与 Chat 私有区分别独立
  - 不允许跨命名空间直接读写
- 仅支持文本文件（不支持二进制文件）。
- 文本文件能力：
  - 基础读写：创建、读取、覆盖写入、删除、重命名、移动
  - 增强读写：append、按行区间 patch（行级更新）
  - 文件级版本能力：历史版本与回滚
- 版本保留策略：
  - 每个文件仅保留最近 N 个版本（N 可配置）
- 提供 UI（文件树/文件操作）与命令接口（供 AI/脚本调用）。

### 不包含范围

- 二进制文件支持（图片、音频、压缩包等）。
- 跨命名空间访问（如 Chat 私有区读取/写入 Global）。
- 权限系统、多用户协作、复杂 ACL。
- 网络同步、云端同步、跨实例共享。

## 功能需求

1. **命名空间管理**
   - 系统必须支持 `global` 与 `chat` 两种命名空间。
   - 所有路径与文件操作都必须显式或隐式归属于其中一个命名空间。

2. **目录与文件基础操作**
   - 支持目录创建、重命名、移动、删除。
   - 支持文本文件创建、读取、覆盖写入、删除、重命名、移动。
   - 删除目录时的行为（递归删除或阻止）需在实现阶段固定为一致策略。

3. **文本增强操作**
   - 支持文件内容 `append`。
   - 支持按行区间 patch（指定起止行或行段替换）。

4. **版本与回滚**
   - 文本文件每次写入（覆盖、append、patch）应形成可回滚版本。
   - 系统必须提供查看历史版本与回滚到指定版本的能力。
   - 每个文件最多保留最近 N 个版本，超出后按时间顺序淘汰最旧版本。

5. **UI 与命令双入口**
   - UI 与命令层必须复用同一核心服务，保证行为一致。
   - 命令接口应覆盖核心操作集合（ls/read/write/append/patch/mv/rm 等等价能力）。

6. **持久化**
   - 数据需在 SillyTavern 会话间持久保存。
   - Global 与 Chat 私有区需使用可区分的数据存储路径/键，避免串写。

## 非功能需求

- **一致性**：同一操作在 UI 与命令接口下结果一致。
- **可维护性**：核心 VFS 逻辑与 UI 解耦，便于后续扩展。
- **可恢复性**：出现误写时可通过版本回滚恢复。
- **容量策略**：不设置插件层“硬性容量上限”，以宿主 chat 存储能力为上限前提。

## 验收标准

1. 可在 Global 与 Chat 私有区分别创建独立目录树，互不影响。
2. 在任一命名空间中可完成：新建文件、读取、覆盖写入、append、按行 patch。
3. 文件发生多次修改后可查看历史版本，并成功回滚到任意保留版本。
4. 当版本数量超过 N 时，系统自动淘汰最旧版本，仅保留最近 N 个。
5. UI 完成一次操作后，命令接口读取到的结果与之一致；反向亦成立。
6. 插件重启后，Global 与 Chat 私有区的数据与版本记录可恢复。
7. 尝试跨命名空间访问时被拒绝并返回明确错误。

## 风险与待确认项

- 当前确认“不设硬上限”，但底层 chat 存储体量存在隐性限制，需在实现后压测并给出建议阈值。
- 目录删除策略（禁止非空目录删除 vs 递归删除）需最终拍板。
- 命令接口具体协议（参数命名、错误码、返回结构）尚需在设计阶段定稿。
- 版本快照粒度（全文快照 vs 增量）未定，可能影响性能与存储开销。
