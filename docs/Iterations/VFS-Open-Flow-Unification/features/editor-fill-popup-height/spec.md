# editor-fill-popup-height 需求说明

## 背景

在当前实现中，进入编辑器后 `textarea.vfs-editor` 在部分场景仅显示很小高度（约几十像素），未占满弹窗内容区，导致可用编辑空间不足、阅读与编辑体验明显下降。

该问题发生在 `VFS-Open-Flow-Unification` 迭代范围内，属于布局回归/样式约束不完整，而非业务交互逻辑问题。

## 目标

- 让编辑区在弹窗内占满可用空间（除顶部工具栏外）。
- 保持编辑区不可手动 resize。
- 确保桌面/移动端一致表现。
- 不引入交互行为变化（本次仅布局修复）。

## 范围

### 包含范围

- 编辑模式下预览容器与 `EditorScreen` 的高度链路（父容器 `flex/min-height` 约束）。
- `textarea.vfs-editor` 的高度、溢出与 resize 行为。
- 对应自动化测试断言更新（布局/样式相关）。

### 不包含范围

- 打开流程、菜单动作、文件/目录行为变更。
- 保存、回滚、未保存确认等业务流程。
- 弹窗整体尺寸策略重设计（仅保证编辑区占满当前可用空间）。

## 功能需求

### FR-1 编辑区占满可用空间

- 在 `mode=editor` 时，`textarea.vfs-editor` 必须占满预览区剩余高度，不得出现仅几十像素高的默认收缩态。
- 父子容器应建立完整高度链路：`preview stack -> preview body -> editor screen -> textarea`，均满足 `flex` 与 `min-height: 0` 的可收缩/可扩展约束。

### FR-2 保持不可手动调整高度

- `textarea` 继续保持 `resize: none`。
- 不因修复高度链路而恢复浏览器默认可拖拽 resize。

### FR-3 跨端一致

- 桌面与移动端编辑模式下，编辑区都应占满可用空间，表现一致。

### FR-4 回归稳定

- 本次变更仅限样式/布局层，不改变打开、保存、返回等现有行为语义。

## 非功能需求

- **可维护性**：采用稳定的 `flex` 高度链路，不依赖一次性行内高度注入。
- **兼容性**：不破坏现有 `vfs-preview-stack` 和 `EditorScreen` 结构。
- **可测试性**：需有可自动化断言的样式行为（至少验证不再出现收缩态与 `resize:none`）。

## 验收标准

| AC | 描述 |
|---|---|
| AC-1 | 编辑模式下，`textarea` 占满预览区剩余高度，不再出现明显过矮（几十像素）状态。 |
| AC-2 | `textarea` 仍为不可手动 resize。 |
| AC-3 | 桌面/移动端行为一致。 |
| AC-4 | `npm run build` 与 `npm run test:run` 通过。 |

## 风险与待确认项

- 预览容器层级中任一节点缺少 `min-height: 0` 都可能导致 flex 子项高度被压缩。
- 若宿主对话框尺寸受外部样式影响，需确保本次修复不依赖宿主注入顺序。
