# VFS 工作树纳入模型重构 PRD

## 背景

当前工作树与 `{{VIRTUAL_WORK_TREE}}` 相关配置中，**列表「灯」所表达的文件启用状态**与**宏中实际是否出现、以何种粒度出现**存在脱节；目录侧「规则」与文件侧「勾选」的优先级依赖实现顺序理解，用户与文档难以给出唯一、可复述的规则。

本需求在**不保留旧配置兼容**的前提下，用统一语义重构：**灯即真相**（与对模型注入结果一致）；**目录规则仅作用于选择「随父目录规则」的文件**；文件夹不承载「展示 / 不展示」，**非根目录**承载**是否对该目录启用纳入规则**；**根目录**提供同等规则配置入口且**规则始终生效**（无关闭）。

## 目标（含成功指标）

- 建立**仅针对文件**的、可判定的**是否纳入工作树**（二态），且与 UI 灯一致。
- 建立**仅针对文件**的**纳入方式**（三态）：显式纳入、显式排除、随父目录规则；**默认**为「随父目录规则」。
- **非根目录**文件夹提供**目录纳入规则是否启用**；启用时，其**直接子文件中**纳入方式为「随父目录规则」者，才套用该目录上配置的**目录纳入规则**（排序、头尾范围、填充方式等）；**不启用则不套用**，且此类「随父目录规则」文件**不纳入工作树**（灯灭、注入不含，见验收标准）。**根目录（`/`）**与其他目录一样提供**目录纳入规则**配置入口，且**不提供「关闭规则」入口**——视为**规则始终生效**；根目录默认规则为 **head = 1000**（在上限内等价于「该目录下受规则约束的子文件全部进入头批」，即**默认等价全部展示**意图；与 tail、fill 的精确组合由 SPEC 对齐数值上界）。
- 成功指标：
  - 任意文件在 UI 上的「纳入 / 未纳入」灯态与宏输出中该文件是否出现、出现粒度**可逐条用验收用例判定一致**。
  - 产品/帮助文档可用不超过一页文字向用户说明优先级，**无需提及实现顺序**。
  - 回归场景覆盖：显式纳入、显式排除、随父目录规则 × 父目录规则开/关、根目录规则入口与默认 head、头批（如 head=3）与灯态一致。

## 用户与场景

- **目标用户**：使用 VFS 工作树向对话上下文注入文件内容的用户；需要精细控制「哪些进、哪些不进、哪些只进摘要」的用户。
- **典型场景**：
  - 少数文件必须始终全文进上下文（显式纳入），其余交给某目录下的头尾 + 填充规则批量处理（随父目录规则 + 目录规则启用）。
  - 某文件明确永不进上下文（显式排除），即使同目录下规则会纳入其他文件。
  - 关闭某目录规则后，依赖「随父目录规则」的文件不再随该目录规则变化，行为符合文案预期。

## 范围

### 包含范围

- **不兼容升级**：不迁移、不读取旧版 `WorkTreeConfig`（含 `selectedFiles`、`directoryRulesEnabled`、`directoryOverrides` 等既有字段）中的工作树纳入语义；以新配置模型为准，**不接受技术债式双轨兼容**（发布说明需告知用户重新配置）。
- 文件侧三态**纳入方式**与二态**是否纳入工作树**（灯 = 结果）的定义、优先级及与宏行为的一致性。
- 文件夹侧：**非根目录**为「目录纳入规则：启用 / 未启用」；**根目录**仅配置规则内容、**无关闭入口**（始终启用）。**不对文件夹**定义「对模型展示 / 不展示」。
- 「随父目录规则」**仅解析直接父目录**：不沿路径递归查找祖父目录；不将「继承」用于易产生递归联想的表述（UI/文档优先使用「随父目录规则」）。
- 命名与文案层面统一对外用语（见下节「术语」），避免「展示策略 / 逻辑状态」等易与「对模型是否可见」混淆的说法；本 PRD 正文采用下列术语。

### 不包含范围

- 具体字段名、序列化格式、渲染算法、任务拆分、接口与模块设计（由后续 SPEC / 实现承担）。
- 除工作树纳入模型以外的 VFS 能力（编辑器、版本历史、快照格式等）除非因本需求**必须**连带变更，否则不在本 PRD 展开。

## 术语（对外与文档统一建议）

| 概念 | 建议用语 | 说明 |
|------|-----------|------|
| 原「展示策略」弹窗所配内容 | **目录纳入规则** | 作用域为**当前目录**；仅影响「随父目录规则」的直接子文件如何被纳入。 |
| 非根文件夹上的开关 | **对此目录启用纳入规则**（或简称 **目录规则**） | 非「文件夹展示」；仅为下游可随规则的文件提供计算入口。**根目录无此开关**，规则始终生效。 |
| 文件侧用户设定（三态） | **纳入方式** | 显式纳入 / 显式排除 / 随父目录规则。 |
| 文件侧结果（二态，与灯一致） | **是否纳入工作树** | 是 = 进入对模型注入集合（及 UI 灯亮）；否 = 不进入（灯灭）。 |

不推荐继续使用「逻辑状态」「展示状态」作为对外主称谓，可改为上表「纳入方式 / 是否纳入工作树」。

## 核心需求（3-7 条）

1. **二态结果仅针对文件**：每个文件有唯一的**是否纳入工作树**；UI 灯仅反映该二态，且与宏（或等价注入输出）一致。
2. **三态纳入方式仅针对文件**，默认 **随父目录规则**：**显式纳入**与**显式排除**的优先级高于「随父目录规则」；**目录纳入规则只对纳入方式为「随父目录规则」的文件生效**。
3. **文件夹无「展示 / 不展示」**：**非根目录**可有**目录纳入规则启用 / 未启用**；**根目录**始终启用规则，仅可编辑规则内容。启用（或根目录默认可编辑）时，该目录已配置的**目录纳入规则**用于计算其**直接子文件**中「随父目录规则」者的纳入结果（含全文 / 文件名 / frontmatter / 不纳入等规则所定义形态，具体形态以后续 SPEC 对齐现有能力集为准）。**未启用**（仅非根）时，「随父目录规则」的直接子文件**不纳入工作树**。
4. **「随父目录规则」只看直接父目录**：不向上递归合并祖父目录规则；祖父目录规则不通过本机制「穿透」到孙级文件。
5. **不兼容旧配置**：新版本仅认新纳入模型；旧 persisted 工作树配置不作为兼容输入（由实现侧选择清空或拒绝加载并提示，以 SPEC 为准；本 PRD 要求**不得**为旧语义保留静默双轨行为）。
6. **默认纳入方式**：新建或未单独设定过的文件，纳入方式为 **随父目录规则**。
7. **根目录规则入口与默认**：根目录提供与其他目录一致的**目录纳入规则**配置入口；无「关闭规则」；**默认 head = 1000**（产品意图：默认等价该目录下「全部展示」；数值上界与 tail、fill 默认由 SPEC 约定并与现有能力对齐）。

## 验收标准

以下均可通过固定目录结构 + 固定目录纳入规则 + 固定文件纳入方式组合，在 UI 与宏输出上**客观判定**。

### 灯与注入一致

- **Given** 某文件「是否纳入工作树」为「是」  
  **When** 用户查看该文件在工作树列表中的灯态，并查看对模型注入结果（宏或等价物）  
  **Then** 灯为「纳入」且该文件在注入结果中按规则或显式设定出现；**不得**出现灯灭但注入仍含该文件，或灯亮但注入不含该文件。

### 显式优先于「随父目录规则」

- **Given** 某文件纳入方式为 **显式纳入**  
  **When** 其父目录「目录纳入规则」为未启用，或规则若启用会将该文件排除  
  **Then** 该文件**仍**纳入工作树（灯亮、注入含该文件），且以「显式纳入」所定义的粒度为准（若 SPEC 约定显式纳入恒为全文，则按 SPEC）。

- **Given** 某文件纳入方式为 **显式排除**  
  **When** 其父目录启用目录纳入规则且规则若作用于「随父目录规则」文件时会纳入该文件  
  **Then** 该文件**不**纳入工作树（灯灭、注入不含该文件）。

### 目录规则仅作用于「随父目录规则」

- **Given** 文件 A 为 **随父目录规则**，文件 B 为 **显式纳入**或**显式排除**  
  **When** 调整同一父目录下的目录纳入规则（头尾、填充等）  
  **Then** 仅 A 的纳入结果随规则变化；B 的行为仅随自身纳入方式变化，**不因**本次规则调整而改变纳入与否（除非 B 为显式纳入且 SPEC 另行约定全文形态，仍不得出现与显式排除矛盾）。

### 父目录规则未启用时的「随父目录规则」文件（已确认，含根目录差异）

- **Given** 某文件纳入方式为 **随父目录规则**，且其**直接父目录**为**非根目录**，且该父目录「目录纳入规则」为**未启用**  
  **When** 用户查看灯态与注入结果  
  **Then** 该文件**不**纳入工作树（灯灭、注入不含），**除非**该文件为 **显式纳入**（与本条 Given 互斥，用于防矛盾用例）。

- **Given** 某文件的**直接父目录为根目录（`/`）**  
  **When** 用户查看根目录规则（始终生效，无关闭入口）及该文件灯态与注入结果  
  **Then** 行为仅由根目录**目录纳入规则**与文件**纳入方式**按全文优先级推导；**不得**出现「根目录规则被关闭」的交互或状态。

### 头批数量与灯态一致（示例 head = 3）

- **Given** 某**非根**目录已**启用**目录纳入规则，`head = 3`，`tail` 与 `fill` 等其余参数在固定夹具下使「排序后的第 1～3 名直接子文件」被规则**纳入工作树**（非「规则侧不展示」），且这三名文件纳入方式均为 **随父目录规则**  
  **When** 用户查看该目录下列表灯态与对模型注入结果  
  **Then** 排序第 1～3 名的文件灯为**亮**（纳入），且注入中出现与灯态一致的纳入内容；第 4 名及以后是否亮灭**与规则是否将其纳入工作树严格一致**（例如规则为「不展示 / omit」导致不纳入者灯灭、注入不含）。

- **Given** 同上目录与 `head = 3`，但某一本应落入头批范围内的文件为 **显式排除**  
  **When** 用户查看灯态与注入  
  **Then** 该文件灯灭、注入不含（显式排除优先于规则头批）。

- **Given** 同上目录与 `head = 3`，但某一排序在头批外的文件为 **显式纳入**  
  **When** 用户查看灯态与注入  
  **Then** 该文件灯亮、注入含（显式纳入优先于规则排序位置）。

- **Given** **根目录（`/`）**规则始终生效，且配置为 `head = 3`，其余参数在固定夹具下使排序后第 1～3 名直接子文件被规则纳入工作树，且该三名文件均为 **随父目录规则**  
  **When** 用户在根下列表查看灯态与注入结果  
  **Then** 与上条「非根目录 + head = 3」一致：第 1～3 名灯亮且注入一致；其余「随父目录规则」子文件亮灭与规则是否纳入严格一致。

### 不兼容

- **Given** 仅存在旧版工作树持久化数据、不存在新模型配置  
  **When** 用户打开工作树相关能力  
  **Then** 行为符合发布说明（例如空白新模型或明确错误提示），且**不得**在无声状态下混用旧 `selectedFiles` / 旧目录门闸语义产生与本文冲突的注入结果。

## 风险与待确认项

1. **模板作用域与聊天作用域**：两桶配置是否同时切换为新模型、文案是否分别提示重置，由 SPEC/发布说明落实。

## SPEC 已定案摘录（与 PRD 对齐，实现以 `spec.md` 为准）

- **显式纳入**：恒为全文。  
- **Markdown + FrontMatter 解析失败**：仍视为纳入工作树（灯亮），宏内保留该文件块，正文降级为「文件名」+ 文件基名 +「，FrontMatter解析失败」；非 Markdown 在「仅文件名」类展示下不出现该失败后缀文案。  
- **从扩展模板覆盖当前聊天**：同步重置聊天侧工作树配置（详见 `spec.md`）。
