# row-menu-open-close-stability 设计方案

## 设计目标

- 修复行菜单“多次点击后不再呼出”的状态卡死问题。
- 修复“点击外部不关闭”的 dismiss 问题。
- 保持与现有 overlay 定位和滚动稳定性修复兼容。

## 总体方案

### 1) 显式控制 toggle 开合状态

- 在 `VfsActionMenu` 中为 `entity-actions` 模式实现可预测开合：
  - 点击 summary 时，允许按当前 open 状态进行开/关切换。
  - 避免只依赖浏览器默认 `details/summary` 在复杂事件链中的非确定行为。

### 2) 统一外部点击关闭机制

- 菜单打开后注册全局点击监听（capture），判断点击是否发生在当前菜单外：
  - 若在菜单外，关闭当前菜单。
  - 若在菜单内，不触发关闭。
- 菜单关闭或组件卸载时清理监听，避免泄漏和重复注册。

### 3) 保持单菜单互斥

- 保留并强化“打开一个菜单前先关闭同容器内其他菜单”逻辑。
- 确保互斥机制与外部点击关闭不冲突。

## 测试策略

### 测试用例

- **TC-1 连续点击稳定**
  - 同一按钮连续点击多次，菜单状态按预期开/关切换。

- **TC-2 外部点击关闭**
  - 打开菜单后点击容器外元素，菜单关闭。

- **TC-3 单菜单互斥**
  - 打开第二个菜单时第一个自动关闭。

- **TC-4 双界面验证**
  - 在 chat/template 场景下至少各覆盖 1 条关键开合路径。

## 风险与回滚方案

- **风险**：全局点击监听若未正确清理，可能引发重复关闭或性能问题。  
  - 缓解：严格在 open/close 生命周期中注册与注销监听。
- **回滚**：
  - 如出现副作用，可回滚 `VfsActionMenu` 的状态管理改动，仅保留已验证稳定部分。
