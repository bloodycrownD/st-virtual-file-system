# row-menu-decouple-selection 需求说明

## 背景与动机

用户实测（mobile `layout-mobile` 与 desktop）：

- **行末三点菜单**：多次点击后仍会进入「失效」状态（无法正常再次呼出或交互异常）。
- **Header 三点菜单**：同样多次点击仍可用，行为稳定。

当前实现中，行菜单与 header 菜单的关键差异之一是：**行菜单在 `toggle-clicked` 时会同步触发列表 `selected`（更新 `selectedPath`）**，进而驱动 `VfsMainScreen` 较大范围的响应式更新；header 的全局创建菜单没有这一步。

用户怀疑「文件选中状态」参与了行菜单的状态机，并提出：**移除列表文件选择状态**，同时要求实现侧明确区分 **header 菜单** 与 **行菜单** 的职责边界（header 作为无 bug 的参照）。

> 命名说明：目录名沿用 `row-menu-decouple-selection`，但本轮用户确认的范围是 **彻底移除列表选中态**（不仅限于解除三点与选中同步）。

## 目标

- 消除行菜单与「列表选中态」之间的耦合，使行菜单的开合/互斥/外部关闭语义与 header 菜单一致稳定。
- **列表 UI 不再展示/维护“当前选中行”**（无 `data-selected` 高亮、无“点行即选中”的交互语义）。
- **预览/编辑等工作上下文**仍可由父级显式维护（例如当前打开的文件路径），但其更新来源应来自**明确的业务动作**（如行菜单触发的 `entity-action-requested`、目录导航等），而不是列表行的“选中同步副作用”。

## 范围

### 包含

- `VfsFileManagerPanel`：移除 `selectedPath` / `data-selected` / `@selected` 列表选中模型；移除行菜单 `@toggle-clicked -> select(path)` 的副作用。
- `VfsMainScreen`：调整与 `selectedPath`（或等价命名）相关的逻辑，使“当前编辑/预览目标”与列表选中解耦；确保行菜单动作路径仍传入 `entity`（现有 `handleRowEntityActionRequested` 已具备 entity override）。
- **chat + template**、**desktop + mobile** 下的回归验证。
- 更新/新增测试：删除或改写依赖「点三点自动选中行」的断言；补充「多次点击行菜单仍稳定」的场景（至少覆盖 mobile 宽度）。

### 不包含

- 变更 `VfsActionMenu` 的全局互斥/外部关闭总体策略（除非解耦后仍复现，才以最小补丁修复）。
- 引入新的手势（长按右键菜单等）。
- 改变 header 菜单动作集合（仍仅为新建目录/新建文件）。

## 功能需求

### FR-1 列表不再维护选中态

- 列表行不再渲染 `data-selected`，不再存在“选中高亮”样式依赖选中路径。
- 行主体点击不再承担「切换选中文件/目录」的产品语义（目录导航仍通过既有规则：至少保留 **双击进入目录**；文件打开方式见 FR-2）。

### FR-2 工作上下文与列表解耦

- **编辑/阅读/幻灯片**等模式的“当前目标路径”由父级状态机维护，更新入口包括（最小集合）：
  - 行菜单触发的实体动作（`entity-action-requested`，携带 entity）
  - 目录导航（Up / 双击进入目录）与会话刷新路径
  - 仍需要的创建/重命名/删除等既有副作用（保持数据一致性）
- 列表组件不再向父级发送「selected」事件。

### FR-3 行菜单与 header 菜单行为对齐（稳定性）

- 在移除列表选中耦合后，行末三点与 header 三点在「多次点击、外部关闭、互斥打开」上应表现一致，不应出现行菜单单独卡死。

## 验收标准

- **AC-1**：`layout-mobile` 与 `layout-desktop` 下，对同一行末三点执行 **连续 20 次**「打开 →（可选）外部关闭 →再打开」不应出现失效（与 header 对照不应更差）。
- **AC-2**：列表不再出现选中高亮；不存在依赖 `data-selected` 的功能回归（测试同步改写）。
- **AC-3**：从行菜单触发查看/编辑等动作仍可作用于正确实体（通过 payload entity，而非依赖列表选中）。
- **AC-4**：目录双击进入、Up 返回等行为保持可用。
- **AC-5**：`npm run test:run -- test/vfs-ui-cr-loop.spec.ts` 通过；涉及其它套件若被连带影响需一并修复；`npm run build` 通过。

## 风险与待确认项

- **文件行单击语义**：移除选中后，单击文件是否应保持无操作（推荐默认），或改为直接进入预览；若需变更，应在实现前与用户确认（本 spec 默认：**单击文件不产生选中；文件操作优先走行菜单或双击策略保持不变**）。
- **测试改造面**：现有用例存在「点三点自动选中行」断言，需要替换为“动作语义”断言，避免继续绑定选中模型。
