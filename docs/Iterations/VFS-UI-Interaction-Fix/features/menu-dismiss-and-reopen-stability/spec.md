# menu-dismiss-and-reopen-stability 需求说明

## 背景

当前“更多操作”菜单（header 菜单 + 行末三点菜单）存在可用性 bug：

- 行末三点：打开菜单后点击外部区域关闭，再次点击三点时菜单可能不再呼出（状态卡死）。
- header 菜单：打开后点击外部区域不关闭，用户需要再次点击或做其它动作才能收起。

此外，现有“同一按钮 toggle 开关”的设计与用户期望不一致：用户希望菜单的消失主要由 **点击外部** 或 **打开其它菜单（互斥）** 驱动，而不是必须依赖再次点击三点按钮。

## 目标

- 彻底修复“关闭后无法再次打开”的卡死问题。
- header 与 row 菜单统一支持“点击外部关闭”。
- 统一互斥规则：打开任意菜单时会关闭其它已打开菜单，并打开新的菜单。
- 三点按钮行为：菜单不存在时点击会打开；菜单存在时点击不要求必须 toggle 关闭（关闭更多由外部点击/互斥触发）。

## 范围

### 包含范围

- header “更多操作”菜单的 dismiss（外部点击关闭）行为。
- row（行末三点）菜单的 reopen 稳定性与 dismiss 行为。
- header 与 row 之间的互斥开关规则。
- 覆盖 chat/template + desktop/mobile。

### 不包含范围

- 不调整菜单动作集合与业务语义（查看/编辑/重命名/删除/创建等）。
- 不引入右键菜单或自动翻转定位策略（仍沿用既有 overlay/right-bottom 方案）。

## 功能需求

### FR-1 外部点击关闭（header + row）

- header 菜单打开后，点击菜单外任意区域必定关闭。
- row 菜单打开后，点击菜单外任意区域必定关闭。
- 外部关闭不得导致列表滚动位置或选中态异常变化。

### FR-2 互斥规则统一

- 打开任意一个菜单（header 或某行 row）时：
  - 关闭其它任何已打开菜单
  - 并打开当前请求的菜单

### FR-3 行菜单可重复打开不卡死

- 复现路径必须修复：
  - 点击行三点打开菜单
  - 点击外部关闭菜单
  - 再点击同一行三点，菜单必须再次出现（可重复多次）

### FR-4 三点按钮行为（非强制 toggle）

- 当菜单**不存在/关闭**时，点击三点应打开菜单。
- 当菜单**已打开**时，再次点击三点可以保持打开或重申打开（不要求必须 toggle 关闭）。
  - 关闭优先由外部点击或互斥切换触发。

## 验收标准

- **AC-1 永不卡死**：按 FR-3 的复现路径重复 10 次，菜单每次都能再次打开。
- **AC-2 外部关闭一致**：header 与 row 菜单都支持点击外部关闭。
- **AC-3 互斥一致**：打开任意菜单都会关闭其它已打开菜单，并打开新的菜单。
- **AC-4 不扰动滚动/选中**：外部关闭后列表滚动位置与选中态保持稳定。
- **AC-5 回归测试**：新增/更新测试覆盖 AC-1~AC-4 的关键路径。

## 风险与待确认项

- 需要避免“菜单内部点击”被误判为外部点击导致菜单提前关闭。
- 互斥关闭逻辑必须只作用于 VFS 弹窗作用域，避免影响宿主页面其它 `details`。
