# create-refresh-immediate 需求说明

## 背景

当前在 VFS 中执行“新建文件/新建文件夹”后，列表不会立即反映最新结果，用户需要重进页面或重开弹窗后才能看到新建项，造成明显的交互断裂：

- 用户误以为创建失败，容易重复提交创建操作。
- 创建成功与界面反馈存在时间差，不符合“即时可见”的常规文件管理体验。
- 在 chat/template 两个入口中都存在同类困扰。

## 目标

- 创建成功后，列表立即刷新并显示新建项。
- 无需重进页面、重开弹窗或切换 tab 才能看到结果。
- 保持当前错误处理行为不变（失败仍按既有提示与状态处理）。

## 范围

### 包含范围

- 本迭代仅覆盖“创建成功后的即时刷新时序”。
- 创建类型：
  - 新建文件
  - 新建文件夹
- 生效界面：
  - 虚拟文件系统（chat）
  - 模板管理（template）
- 生效布局：
  - desktop
  - mobile

### 不包含范围

- 不调整创建输入规则（名称校验、非法字符、`.`/`..` 规则等）。
- 不新增创建成功后的自动跳目录、自动打开编辑器等额外行为。
- 不改动失败时提示文案与错误映射策略（沿用当前基线行为）。
- 不在本迭代引入任何新的失败路径校验或错误映射语义变更。

## 功能需求

### FR-1 创建成功后即时刷新

- 当创建操作成功提交并写入快照后，当前目录列表必须立即反映新建项。
- 不依赖页面重载、弹窗重开、tab 切换等外部动作触发刷新。

### FR-2 刷新范围精确

- 仅刷新受影响的当前目录列表与必要选择态，不引入整页闪烁或不必要重渲染抖动。
- 已有目录路径上下文保持稳定（不跳到其它目录）。

### FR-3 两类创建行为一致

- 新建文件与新建文件夹均遵守同一“成功即见”反馈规则。
- chat/template 两个 scope 体验一致。

## 非功能需求

- **一致性**：desktop/mobile 行为一致。
- **可维护性**：刷新触发逻辑集中在创建成功路径，避免分散在多个组件事件中。
- **兼容性**：不影响现有 `VfsActionMenu`、`VfsCreateEntityModal` 与快照持久化链路。
- **边界约束**：失败路径行为以当前主线基线为准，本特性不新增失败路径改动。

## 验收标准

- **AC-1 即时可见**：创建成功后，新项在当前列表立即出现，无需重进页面。
- **AC-2 范围覆盖**：文件/文件夹两类创建都满足 AC-1。
- **AC-3 双界面一致**：chat/template 两个界面均满足 AC-1。
- **AC-4 双布局一致**：desktop/mobile 均满足 AC-1。
- **AC-5 失败不回归**：创建失败时，现有错误提示与状态行为保持不变。

## 风险与待确认项

- 若当前刷新依赖特定组件 key 或生命周期，修复时需避免过度重建导致光标/滚动位置不稳定。
