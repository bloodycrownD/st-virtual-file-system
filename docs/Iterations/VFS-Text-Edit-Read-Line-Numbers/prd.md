# VFS 文本编辑行号 PRD

## 背景

当前文本编辑体验缺少行号，用户在定位内容、沟通修改位置与核对差异时成本较高。为提升可读性与协作效率，需要在**源码编辑**场景提供稳定、低调的逻辑行号能力。

渲染后的阅读/预览为富文本布局，与「按换行符划分的逻辑行」无法一一对应；在预览侧强行展示行号易误导用户，因此行号仅保留在源码编辑态。

## 目标（含成功指标）

- 在**源码编辑**（非预览）中提供逻辑行号（按换行符分隔，自 1 递增），默认开启、无需配置。
- 行号视觉风格贴近常见编辑器（如 VS Code）：**仅弱化数字，无独立色条/粗分隔线**，不抢夺正文注意力。
- 成功指标：
  - 行号准确率：增删改与刷新后，逻辑行号连续正确，核心场景 100%。
  - 滚动同步：源码区滚动时，行号与 `textarea` 垂直对齐、同步滚动。
  - 可读性：预览/阅读模式无行号；源码模式下行号低调、不形成明显「行号条」。

## 用户与场景

- 目标用户：使用 VFS 进行文本创建、编辑、阅读与校对的全部用户。
- 典型场景：
  - 在源码编辑区按「第 N 行」定位与修改。
  - 在沟通中引用逻辑行号（对应磁盘/编辑器中的换行语义）。

## 范围

### 包含范围

- **仅**在 `EditorScreen` 的源码模式（`previewMode === false`）中，于 `textarea` 左侧展示逻辑行号。
- 所有文本文件在源码编辑时统一展示行号（无按类型开关）。
- 行号默认始终显示于源码编辑态，不提供用户级开关。

### 不包含范围

- 预览渲染、独立阅读页（`ReaderScreen`）、幻灯片阅读等**不**展示行号。
- 不包含按视觉软换行的行号（仅逻辑行）。
- 不包含按文件类型单独配置行号策略。

## 核心需求（3-7 条）

1. 系统在源码编辑区展示逻辑行号，与当前文本实时一致。
2. 系统在进入编辑预览（渲染 Markdown）时**不**展示行号。
3. 行号与源码区垂直对齐，滚动时同步。
4. 行号样式弱化：透明底、无整条竖向色带、无强调分隔线；等宽数字、右对齐。
5. 内容增删改或刷新后，行号立即更新并保持连续。

## 验收标准

- [ ] Given 打开文件进入源码编辑，When 文本有 N 个逻辑行，Then 显示 1..N 的连续行号，且与每一逻辑行对应。
- [ ] Given 在源码编辑中增删换行，When 编辑完成，Then 行号立即重算，无重复/跳号。
- [ ] Given 处于编辑预览（渲染）模式，When 查看正文，Then **不**出现行号 gutter。
- [ ] Given 独立阅读模式或幻灯片阅读，When 查看正文，Then **不**出现行号 gutter。
- [ ] Given 源码区滚动，When 任意滚动位置，Then 行号与正文同步，无明显错位。
- [ ] Given 长文本与多段落，When 查看 gutter，Then 无整条高对比「行号条」观感（透明底、无竖线分隔亦可接受）。
