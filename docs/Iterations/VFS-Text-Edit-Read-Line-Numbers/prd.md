# VFS 文本编辑/阅读行号 PRD

## 背景

当前文本编辑与阅读体验缺少行号，用户在定位内容、沟通修改位置与核对差异时成本较高。为提升可读性与协作效率，需要在编辑与阅读场景统一提供行号能力。

## 目标（含成功指标）

- 在编辑模式与阅读/预览模式中提供统一、稳定的逻辑行号显示能力。
- 成功指标：
  - 行号准确率：针对增删改与内容刷新后的行号显示，核心场景准确率达到 100%。
  - 交互一致性：滚动时行号与正文保持同步，无明显错位（验收用例全通过）。
  - 可读性达标：行号存在但不干扰正文阅读（通过视觉验收清单）。

## 用户与场景

- 目标用户：使用 VFS 进行文本创建、编辑、阅读与校对的全部用户。
- 典型场景：
  - 编辑文本时快速定位某一行进行修改。
  - 阅读/预览文本时根据行号进行内容核对与问题反馈。
  - 在沟通中通过“第 N 行”明确定位问题与变更建议。

## 范围

### 包含范围

- 编辑模式（源码编辑区）显示逻辑行号（按换行符分隔，自 1 递增）。
- 阅读/预览模式显示逻辑行号（按换行符分隔，自 1 递增）。
- 所有文本内容类型统一支持行号显示。
- 行号默认始终显示，不提供开关。

### 不包含范围

- 不包含按视觉换行行号（软换行后的每一折行编号）。
- 不包含按文件类型自定义显示策略。
- 不包含本阶段技术实现细节、接口设计或性能优化方案设计。

## 核心需求（3-7 条）

1. 系统应在编辑模式中展示逻辑行号，且与当前文本内容实时一致。
2. 系统应在阅读/预览模式中展示逻辑行号，编号规则与编辑模式一致。
3. 系统应确保行号与正文垂直对齐，并在滚动时保持同步。
4. 系统应对所有文本内容启用行号显示，无需额外配置。
5. 行号样式应清晰可辨且弱化于正文，不影响正文阅读优先级。
6. 当文本内容发生增删改或刷新后，行号应立即更新并保持连续正确。

## 验收标准

- [ ] Given 打开任意文本进入编辑模式，When 文本有 N 个逻辑行，Then 显示 1..N 的连续行号，且与每一逻辑行对应。
- [ ] Given 在编辑模式中新增、删除或合并行，When 操作完成，Then 行号立即重算并保持连续无重复/跳号。
- [ ] Given 打开同一文本进入阅读/预览模式，When 内容不变，Then 行号总数与编辑模式一致。
- [ ] Given 内容区域发生滚动，When 任意滚动位置，Then 行号列与正文行保持对齐且同步滚动，无明显错位。
- [ ] Given 文本存在长段内容与多段落，When 显示行号，Then 行号可清晰辨识且不压制正文可读性。
- [ ] Given 任意受支持文本内容类型，When 打开编辑或阅读/预览，Then 默认可见行号且无需用户手动开启。
