# 虚拟工具调用执行 需求说明

## 背景

当前插件已具备消息事件封装与 VFS 基础能力。为了让模型在聊天消息中触发可控文件操作，需要新增“虚拟工具调用”机制：从消息文本解析工具调用 JSON，执行工具，并保证同一调用不会重复生效。  
同时，VFS 需要支持 chat 级持久化、chat 级日志与版本管理；此外还要支持 extension 级模板 VFS，用于初始化新 chat。

## 目标

- 在 `st-virtual-file-system` 内实现消息驱动的虚拟工具调用执行链路。
- 以 `<virtual-tool-call>...</virtual-tool-call>` 标签承载工具调用请求，支持多工具调用。
- 工具操作目标为 **chat 级 VFS**，不触达真实本地文件系统。
- 执行后移除工具调用标签内容，避免重复执行。
- 执行结果写回 `<virtual-tool-result>` 标签，形成可审计执行记录。
- 引入 chat 级独立日志系统（无 TTL；每 chat 容量默认 1MB 且可配置，可清理）。
- 引入 chat 级版本管理：一次工具调用批次可视为一次 commit。
- 支持 extension 级 VFS 作为模板克隆来源（仅人工维护，不参与 tool call 和版本管理）。

## 范围

### 包含范围

- 在消息接收与消息编辑事件触发时解析工具调用。
- 解析规则：
  - 仅取消息中最后一个 `<virtual-tool-call>...</virtual-tool-call>` 标签块。
  - 标签内容为 JSON，支持多工具调用请求。
- 执行后处理：
  - 将被执行的 `<virtual-tool-call>...</virtual-tool-call>` 标签块原子替换为 `<virtual-tool-result>...</virtual-tool-result>`。
  - 若消息中存在多个 `<virtual-tool-result>` 标签块，视为执行错误并拒绝本次执行（写日志）。
- 实现工具系统及以下工具：
  - `read`
  - `write`
  - `delete`
  - `update`
  - `append`
  - `list`
  - `search`
- 实现 chat 级独立日志系统（本次必须实现，不是占位接口）：
  - 记录工具调用请求、执行结果、失败原因、时间戳、消息索引等上下文。
  - 每 chat 容量上限默认 1MB（可配置）、支持主动清理。
- 实现 chat 级版本管理系统：
  - 一次消息触发的一批工具调用作为一次“事务型 commit”。
  - 人工保存操作也产生 commit，保证语义统一。
- `read/write/update` 需满足可控性约束（见“功能需求”）。
- 实现双层 VFS 生效域：
  - chat 级 VFS：可被工具访问、可持久化、带日志与版本管理。
  - extension 级 VFS：不可被工具访问、仅人工更新、无版本管理，可作为模板克隆到 chat 初始化。

### 不包含范围

- 真实本地文件系统操作。
- 远程工具调用、网络工具执行。
- extension 级 VFS 的自动版本管理。

## 功能需求

1. **事件触发**
   - 在消息接收（`MESSAGE_RECEIVED`）和消息编辑（`MESSAGE_EDITED`）时执行虚拟工具解析与调度。

2. **标签提取、并发控制与去重执行**
   - 从消息正文中提取最后一个 `<virtual-tool-call>` 标签块。
   - 当标签不存在或内容为空时跳过。
   - 同一 `messageId` 执行过程需加锁，避免接收/编辑事件并发导致重复执行。
   - 成功进入执行流程后，移除该标签块内容（或整块），确保不会重复触发。
   - 执行完成后写入 `<virtual-tool-result>` 标签块，包含调用入参摘要、工具名、执行结果（成功/失败）等结构化信息。

3. **调用协议（JSON）**
   - 使用固定 schema：`{ "calls": [{ "tool": "...", "args": { ... } }] }`。
   - 每个调用项至少包含：工具名、参数对象。
   - 非法 JSON 或非法工具名必须被拒绝并记录日志。
   - 单次消息最多 10 个工具调用。
   - 单次批量执行总超时 5 秒，超时视为失败。

4. **批量调用执行语义（原子性）**
   - 批量调用按顺序执行。
   - 任一工具失败，后续工具不再执行（fail-fast）。
   - 保证原子性：失败时本批次已执行改动必须回滚，结果回到执行前状态。
   - 采用“内存执行完成后一次持久化”的原子实现策略。
   - 若执行成功，则整体提交为一次 commit。
   - 默认不自动重试失败工具调用。
   - 同一批次内的多次 `update` 采用**串行状态传递**：后一个调用读取的是前一个调用已生效后的工作副本内容。
   - 多次 `update` 的最终结果不做“文本层手工合并”步骤；以串行执行后的最终工作副本作为批次结果。
   - 若后续 `update` 因行号漂移或 `expected old content` 不匹配而失败，整批回滚并记为失败。

5. **工具行为**
   - `read`：支持按路径读取，可指定行范围。
   - `write`：按路径写入，自动创建缺失父目录。
   - `delete`：删除文件或目录；删除目录必须显式 `recursive=true`。
   - `update`：按行更新，必须提供目标行信息与原文校验。
   - `append`：在文件末尾追加内容。
   - `list`：列目录内容。
   - `search`：默认纯文本不区分大小写匹配；可选 `regex=true` 启用正则模式。

6. **read 限制（AI 上下文优化）**
   - 默认单次最多返回 500 行且总文本不超过 20k 字符。
   - 当调用指定行范围时，仅返回指定范围（仍需受总字符上限保护或明确截断策略）。
   - 超限时返回截断标识并记录日志。

7. **update 安全约束**
   - 请求必须包含待更新行号/范围。
   - 请求必须包含“原文内容（expected old content）”。
   - 仅当 expected old content 与真实文本完全一致时才执行更新；不一致则拒绝并记录日志。

8. **chat 级独立日志系统**
   - 提供结构化日志记录，至少包含：
     - `timestamp`
     - `chatId`
     - `messageId`
     - `batchId` / `commitId`
     - `toolName`
     - `status`（success/failed/timeout/skipped）
     - `durationMs`
     - 参数摘要
     - 错误码与错误信息（如有）
   - 日志可与消息结果标签并存：标签用于模型可见反馈，日志用于系统观测与排障。
   - 提供基础查询能力（如按消息 id 或时间范围查询）。
  - 提供清理能力：支持手动清理。
  - 保留策略：按 chat 维度容量上限控制（默认 1MB，可配置），超限时淘汰最旧日志；不设置 TTL。

9. **版本管理（chat 级）**
   - 一次工具调用批次（通过原子性校验后）产生一次 commit。
   - 一次人工保存操作产生一次 commit。
   - commit 至少记录：提交时间、触发来源（tool/manual）、摘要、变更文件列表（可摘要）。
   - 版本管理仅对 chat 级 VFS 生效，不作用于 extension 级 VFS。

10. **双层 VFS 生效域与初始化**
   - chat 级 VFS：工具可访问、日志与版本管理生效、数据持久化到 chat 级存储。
   - extension 级 VFS：仅人工更新，工具不可访问，无版本管理。
  - chat 初始化时首次访问自动从 extension 级 VFS 模板克隆初始文件/目录结构（幂等）。
   - 支持手动触发“模板覆盖现有 chat VFS”。
   - 持久化映射固定为：chat VFS -> `chatMetadata`，extension VFS -> `extensionSettings`。

## 非功能需求

- **幂等性**：同一消息中同一标签块不会重复执行。
- **可维护性**：工具调度、工具实现、消息解析、日志记录、版本管理分层解耦。
- **可靠性**：批量工具调用支持失败回滚，错误可审计。
- **可扩展性**：后续新增工具时无需修改核心调度骨架。
- **可观测性**：日志可用于排查“是否触发、执行了什么、为什么失败”。
- **资源控制**：单次批量 10 调用 + 5 秒超时，防止异常资源占用。

## 验收标准

1. 消息含 `<virtual-tool-call>` 时，在接收/编辑事件能触发解析执行。
2. 仅最后一个标签块会被执行；执行后标签块被清空/移除，不会再次生效；并发触发不会重复执行。
3. 执行后会写入 `<virtual-tool-result>`，包含工具名、参数摘要、成功/失败结果。
4. 七个工具均可被调度并作用于 chat 级 VFS（非真实文件系统）。
5. 批量调用语义满足：任一失败立即终止并整体回滚；成功则整体提交一次 commit。
6. 单次调用资源限制生效：最多 10 工具调用，超时 5 秒会失败并记录。
7. `read` 满足默认 500 行 + 20k 字符限制，支持行范围读取。
8. `update` 在原文不匹配时拒绝执行；匹配时成功更新。
9. chat 级日志系统可查询，满足“每 chat 容量上限（默认 1MB、可配置）+ 手动清理”。
10. chat 级版本管理可记录 tool/manual 两类 commit。
11. extension 级 VFS 不可被 tool call 访问、无版本管理；可作为 chat 初始化模板克隆，并支持手动模板覆盖 chat。
12. 存在测试或等价验证覆盖：标签解析、去重并发、批量原子回滚、read 限制、update 校验、资源限制、日志清理、版本提交、模板克隆。

## 风险与边界说明

- 批量执行限制已固定：整批超时 5 秒、每消息最多 10 个调用（实现为可配置项并给默认值）。
- `<virtual-tool-result>` 采用结构化字段输出；错误码使用统一字典并在实现时落地常量。
- 模板覆盖默认策略为“覆盖前自动生成一次 chat 级版本快照（commit）”，用于人工回退。
