# 虚拟工作树 UI 挂载与工程实现需求说明

## 背景

SillyTavern 可用挂载点有限，本迭代需要在 `.extraMesButtons` 完成稳定挂载，并以 jQuery 驱动入口生命周期。同时满足阅读/预览的安全渲染与日志大数据量性能要求。

## 目标

- 定义 `.extraMesButtons` 挂载规范与生命周期管理。
- 定义弹窗容器、事件绑定、销毁清理的工程约束。
- 定义 markdown/html 渲染与 sanitize 的统一策略。
- 定义日志列表在大数据量下的性能基线方案。

## 范围

### 包含范围

- jQuery 挂载、解绑、防重复注入策略。
- 弹窗 Tab 容器初始化与销毁时序。
- 渲染库选择与 sanitize 统一链路约束。
- 日志列表分页方案的工程要求。

### 不包含范围

- 替换 SillyTavern 原生挂载机制。
- 全量 UI 样式设计系统建设。
- 与本迭代无关的后端基础设施重构。

## 功能需求

1. **挂载规范**
   - 入口必须挂载到 `.extraMesButtons`。
   - 每次初始化前检查是否已挂载，避免重复按钮和重复事件绑定。
   - 提供销毁函数，在页面离开/重载时解绑事件并释放引用。

2. **弹窗容器工程化**
   - 弹窗作为统一壳层承载 Tab1/Tab2/Tab3。
   - 容器与业务状态层解耦，便于后续替换视图库或重构。
   - 所有异步请求均需有加载态、错误态；错误态统一使用官方 `toastr` toast。
   - 错误码仅在 `toastr.error` 展示，格式固定为：`[E_<REASON>] 人类可读错误信息`。
   - 不提供重试按钮。

3. **渲染与安全**
   - 阅读页与编辑页预览共用同一渲染链路。
   - markdown/html 输出前统一经过 sanitize。
   - sanitize 默认采用 `loose` 白名单策略。
   - 白名单默认允许常用内容标签（标题、段落、列表、表格、引用、代码、图片、链接、分隔线、行内格式）。
   - 默认移除脚本相关标签、内联事件属性和 `javascript:` 协议链接。
   - 对 `style`、`iframe`、`object`、`embed`、`form` 类高风险能力默认禁用。
   - 禁止执行危险脚本与内联事件处理器。

4. **日志性能**
   - 日志列表仅采用分页，避免一次性渲染全量。
   - 默认每页 `20` 条。
   - 默认手动刷新；发生消息编辑或收到消息事件时自动刷新一次。
   - 支持按时间序加载与增量更新。
   - 失败日志高亮策略不应显著拖慢渲染。

5. **参考策略**
   - `st-better-database/src/app` 可作为轻量参考（样式与结构思路）。
   - 当前实现不强依赖其架构与代码约束。

## 非功能需求

- **稳定性**：挂载/销毁可重复执行，长期运行不泄漏。
- **安全性**：渲染链路可防 XSS 类风险。
- **性能**：日志大数据量下保持可滚动、可操作。
- **可维护性**：挂载层、状态层、展示层边界清晰。

## 验收标准

1. 多次进入/离开页面后，`.extraMesButtons` 仍仅有一个入口实例。
2. 不存在重复事件触发、重复弹窗实例、明显内存增长异常。
3. 阅读页与预览页对同一内容渲染结果一致，且危险内容不执行。
4. 日志量上升后，列表仍可流畅操作（仅分页生效）。
5. 核心异步流程均有加载/错误反馈，错误通过官方 `toastr` 统一提示并带错误码，且无重试按钮。

## 风险与待确认项

- `loose` 白名单策略下需通过实际样本校验危险输入拦截效果与渲染可用性平衡。
- 日志增长速度与保留策略会影响分页参数选型与接口压力。

## 已确认决策（2026-05-08）

- 挂载生命周期采用“事件委托 + on/off 成对清理 + 幂等挂载检查”。
- 阅读页与预览页共用统一渲染链路，并统一 sanitize 配置（默认 `loose`）。
- 日志列表仅采用分页方案，默认每页 `20` 条。
- 错误反馈统一采用官方 `toastr` toast，展示错误码，不提供重试按钮。
- 错误码命名采用短码风格 `E_<REASON>`，并以前置方式展示。
