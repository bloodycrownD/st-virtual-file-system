# 虚拟工作树 UI 所见即所得 需求说明

## 背景

当前已规划后端宏渲染能力（`VIRTUAL_FILE_TREE`、`VIRTUAL_WORK_TREE`）。本迭代聚焦 UI：让用户在界面中配置“哪些文件被 AI 看到、按什么顺序看到、以什么粒度看到”，并确保 UI 预览与宏最终输出一致。

## 目标

- 提供可视化工作树界面，展示 chat 级 VFS 目录与文件。
- 支持文件/文件夹读取策略配置，并实时反映在预览区。
- 保证“UI 所见即所得”：UI 预览顺序与 `VIRTUAL_WORK_TREE` 渲染顺序一致。
- 复用现有后端协议，不在前端重新定义另一套规则。

## 范围

### 包含范围

- 目录树浏览：
  - 进入目录查看文件列表。
  - 返回上级目录。
- 文件读取状态：
  - 文件可被设置为“读取”（显式 selected）。
  - 读取文件在预览区完整展示为 `<file ...>...</file>` 格式。
- 文件夹策略配置（目录规则）：
  - 排序方式：名称 / 创建时间 / 更新时间。
  - 排序方向：升序 / 降序。
  - 头部读取：`0~1000`。
  - 尾部读取：`0~1000`。
  - 填充策略：文件名 / FrontMatter读取 / 不展示。
  - 文件夹读取状态为一等状态，仅在“读取”状态下目录规则生效；**仅控制该文件夹上的目录规则是否参与计算**，不表示整棵子树自动按该规则展开。
- 预览区：
  - 预览 AI 最终看到的工作树文本（`VIRTUAL_WORK_TREE` 等价结果）。
  - 行号从 1 开始，格式 `N|内容`。
- 与后端联动：
  - UI 保存 chat 配置。
  - extension 配置可作为模板初始化 chat 配置（由后端提供能力，UI 提供触发入口）。

### 不包含范围

- 本迭代不实现新的宏渲染算法（仅消费既有后端协议）。
- 本迭代不改动真实本地文件系统。
- 本迭代不实现跨 chat 的批量配置管理。

## 功能需求

1. **页面结构**
   - 左侧：目录树/当前目录文件列表。
   - 右侧：策略面板 + 预览面板。
   - 支持空状态（无文件、无配置、加载失败）。

2. **显式读取（selectedFiles）**
   - 用户可将文件标记为读取状态。
   - 读取状态应立即体现在预览区。
   - 同一文件重复操作不产生重复项。

3. **目录策略配置**
   - 每个目录可配置独立规则；未配置时继承全局默认规则。
   - `headCount/tailCount` 输入超过 `1000` 时，前端展示归一化后的值 `1000`。
   - 当 `head/tail` 区间重叠时，预览按并集展示（覆盖即展示），不丢文件。

4. **FrontMatter 展示**
   - 仅 markdown 文件参与 FrontMatter 展示。
   - 非 markdown 文件在该策略下不展示。
   - markdown 文件若 FrontMatter 不存在或解析失败，不展示。
   - UI 文案需明确“仅展示 FrontMatter，正文省略”。

5. **预览与顺序一致性**
   - UI 预览顺序必须与后端渲染顺序一致。
   - 对名称排序场景，沿用“同目录文件名唯一”前提，不额外引入二级排序键。

6. **保存与恢复**
   - 支持保存当前 chat 工作树配置。
   - 支持从 extension 模板克隆初始化（若用户触发）。
   - 刷新后可恢复上次保存的配置与预览状态。

## 数据与交互约束

- 前端不自行“猜测”渲染结果；以后端返回或统一渲染函数为准。
- `selectedFiles` 优先级高于目录规则（与后端一致）。
- 最终输出按路径去重，同一路径最多展示一次。
- `updatedBy` 枚举严格为 `user|assistant`。
- 输入非法值（负数、非数字）时，前端应阻止提交并给出提示。

## 非功能需求

- **一致性**：UI 与宏结果 100% 对齐，避免“看见的不等于发给 AI 的”。
- **可用性**：常见操作（选文件、改策略）反馈及时，预览更新可感知。
- **可维护性**：目录树状态、策略状态、预览状态分层管理。
- **健壮性**：后端异常时不崩溃，提供明确错误提示和重试入口。

## 验收标准

1. 用户可在 UI 浏览目录并对文件设置读取状态。
2. 用户可配置目录排序、方向、头尾读取、填充策略并生效到预览。
3. `headCount/tailCount` 超过 `1000` 时自动归一化为 `1000`。
4. `head/tail` 重叠时，预览按并集展示且去重后不丢文件。
5. FrontMatter 策略下 markdown 文件可见 FrontMatter，正文不展示；非 markdown 或解析失败不展示。
6. UI 预览顺序与 `VIRTUAL_WORK_TREE` 实际输出顺序一致。
7. 刷新后可恢复已保存配置；可从 extension 模板初始化 chat 配置。
8. 文件夹未处于读取状态时，其目录规则不参与预览计算。

## 风险项

- 目录树组件选型（现有组件复用或新建）对实现周期有影响。
- 大目录（>1000 文件）下预览性能与交互流畅度需要压测。
- FrontMatter 的前端提示文案应固定为“仅 markdown 展示，非 markdown 或解析失败不展示”，避免实现偏差。
