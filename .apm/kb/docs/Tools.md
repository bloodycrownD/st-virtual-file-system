# 虚拟工具调用（使用者说明）

在**已启用**本扩展的虚拟工具功能时，你可以在**某条聊天消息的正文里**写一段固定格式的「调用」，扩展会在消息落库后自动执行，并把这段调用**换成**一段「结果」。  
所有操作都只针对**当前聊天的虚拟文件系统**里的路径，不会读写你电脑上的真实磁盘。

---

## 调用长什么样（`<virtual-tool-call>`）

在消息里放入一对标签，中间是一段 **JSON**（须为合法 JSON；扩展设置中可开启**保守的 JSON 自动修复**，仅作用于本标签通道）：

```text
<virtual-tool-call>{"calls":[{"tool":"write","args":{"path":"/notes/hello.txt","content":"你好\n"}}]}</virtual-tool-call>
```

含义拆开看：

- 最外层是一个对象，里面只有一个键 **`calls`**，值是**数组**。
- 数组里每一项是一次工具调用，至少包含：
  - **`tool`**：字符串，要写下面「支持的函数」里列出的名字。
  - **`args`**：对象（即使是空的也要写成 `{}`），里面放该工具需要的参数。

**一批里可以写多条调用**（多个 `{ "tool", "args" }`），会按顺序依次执行；单条消息里**一批最多 10 条**，整批有**总时间上限**（超时则整批失败，已执行完的仍会保留在结果里，具体以界面日志为准）。

**若同一条消息里写了多段 `<virtual-tool-call>...</virtual-tool-call>`**：只有**最后一段**会被执行，前面的会被当成历史/草稿忽略。想改调用时，可以新写一段放在后面。

虚拟路径习惯以 **`/`** 开头，例如 `/readme.md`、`/docs/note.txt`。

---

## 结果长什么样（`<virtual-tool-result>`）

执行结束后，扩展会把**原来的那一段 `<virtual-tool-call>...</virtual-tool-call>`**整段替换成：

```text
<virtual-tool-result>{"ok":true,"calls":[...],"results":[...]}</virtual-tool-result>
```

中间同样是一段 **JSON**，常见字段含义：

| 字段 | 含义 |
|------|------|
| **`ok`** | 整批是否全部按预期跑完。`false` 表示中途有错或超时等。 |
| **`calls`** | 本次尝试的调用列表。**成功**时每项为 `{ tool, argsSummary }`（仅参数名，如 `path,content`）。**失败**时每项为 `{ tool, args }`（**完整入参**，便于排错）。JSON 解析失败时可能含 `args.callContent` 为原始 call JSON。 |
| **`results`** | 与 `calls` **一一对应**的每条结果（见下表）。若中途失败，可能只有前面几条有结果。 |
| **`errorCode` / `errorMessage`** | 当 `ok` 为 `false` 时，说明失败原因（例如 JSON 写错、未知工具名、超时等）。 |

**`results` 里每一项**通常包含：

| 字段 | 含义 |
|------|------|
| **`tool`** | 对应哪个工具。 |
| **`ok`** | 这一条是否成功。 |
| **`summary`** | 给人看的短句说明（例如「写入了某路径」）。 |
| **`data`** | 部分工具会附带结构化数据（例如 `read` 读出的一段正文、`list` 列出的条目）；没有则为空。 |
| **`errorCode`** | 这一条失败时的错误码（若有）。 |

一条消息里**最多应只出现一段** `<virtual-tool-result>`；若你手动复制出多段结果标签，扩展会认为状态异常而**不再执行**新的调用，直到你改回正文。

## 支持的函数（`tool` 名与常用 `args`）

下面每一项的 **`args` 都必须是对象**。未写明的参数一般可省略（工具会用默认值）；**路径类**参数通常要求非空字符串。

### `read` — 读文件（可截断）

- **`path`**（必填）：要读的文件路径。
- **`startLine`**：从第几行开始读，默认从第 1 行起（从 1 计数）。
- **`endLine`**：读到第几行为止；有默认上限，与 `startLine` 一起限制行数。
- **`maxLines` / `maxChars`**：进一步收紧返回行数、字符数（不能超过扩展内置的硬上限）。

成功时 **`data`** 里通常会有 `content`（读到的正文）、以及是否被截断等说明。

### `write` — 写入或覆盖文件

- **`path`**（必填）：文件路径。
- **`content`**：要写入的字符串；不写则当作空字符串。  
  若父文件夹不存在，扩展会**自动创建**父路径，一般不必单独建目录。

### `append` — 在文件末尾追加

- **`path`**（必填）。
- **`content`**：追加的字符串；不写则当作空。若文件尚不存在，会先当作空文件再追加。

### `delete` — 删除文件或目录

- **`path`**（必填）。
- **`recursive`**：只有在你明确写成 **`true`** 时，才允许**递归删除目录**；不写或 `false` 时按非递归语义，避免误删整棵树。

### `replace` — 按片段精确替换（推荐）

- **`path`**（必填）。
- **`oldContent`**（必填，非空）：文件中要查找的**完整旧片段**，必须与文件内容**完全一致**（含空格、换行）。
- **`newContent`**（必填）：替换成的新文本；写成空字符串表示删除该片段。
- **`replaceAll`**：默认不写或 `false` 时，**只允许出现一次** `oldContent`（多处命中会报错，避免误改）；写成 **`true`** 时替换文件中**全部**匹配。

适合在文件中间改几行、改一个词，不必数行号。锚点片段尽量选**足够长且唯一**的一段上下文。

### `list` — 列出目录下的条目

- **`path`**（必填）：目录路径。  
  成功时 **`data`** 为条目列表（名称、类型等，供界面或其它逻辑使用）。

### `search` — 在虚拟树里搜文件内容

- **`query`**：要搜的字串；不写则相当于空查询。
- **`regex`**：写成 **`true`** 时按正则匹配（大小写不敏感）；否则按普通子串匹配。
- **`path`**：从哪个目录开始往下搜，默认从根 `/` 搜。

成功时 **`data`** 里常见 `matches`：命中的文件路径列表。

## 使用上容易踩坑的几点

1. **标签名、JSON 都要写对**：标签是 `<virtual-tool-call>` / `</virtual-tool-call>`。无法解析且未通过保守修复时，**不会**写入失败型 `<virtual-tool-result>`，原 call 块保留以便改正后重试；高把握的结构问题（如少 `}`、尾逗号）在开启自动修复时可能自动补全并执行。  
2. **每条调用都要有 `args` 对象**，不能写成 `null` 或数组。  
3. **工具名拼写**必须与上表一致（全小写英文），否则整批会报「不支持的工具」。  
4. 同一条消息里**不要留多段 `<virtual-tool-result>`**；正常情况扩展执行一次就只会留下一段结果。

若扩展设置里关闭了虚拟工具功能，你写在消息里的调用块会被忽略，不会执行也不会被替换。
