# 虚拟文件系统序列化实现 需求说明

## 背景

当前插件需要一个可用于上层业务的虚拟文件系统能力。由于运行环境和持久化通道要求数据可 JSON 序列化，因此底层实现必须围绕可序列化对象进行设计。同时，文本内容需要考虑压缩策略，以降低存储体积并保持后续扩展能力。

## 目标

- 提供一个对上层友好的文件系统接口（外部语义接近常见文件系统）。
- 提供不绑定具体存储介质的抽象层，便于后续接入 ST 或其他后端。
- 保证可序列化（JSON 友好）数据模型。
- 将内容压缩纳入设计与实现（至少支持文本内容压缩策略）。

## 范围

### 包含范围

- 实现完整的 VFS 核心能力（扩展档）：
  - `mkdir`
  - `list`
  - `readFile`
  - `writeFile`
  - `delete`
  - `exists`
  - `move`
  - `rename`
  - `stat`（至少包含 `size`、`mtime`）
  - `copy`
  - `touch`
  - 递归删除
  - 目录遍历
- 设计并实现存储抽象接口（Repository/Driver），不直接绑定 ST `extensionSettings/chatMetadata`。
- 设计并实现可 JSON 序列化的持久化快照结构。
- 内容压缩能力纳入实现（仅压缩文件内容，不压缩路径和元数据）。
- 提供全量实现，而非仅接口或文档。

### 不包含范围

- 版本管理（commit/snapshot 历史、diff、checkout、branch/merge）。
- 权限系统、ACL、用户隔离。
- 文件锁、并发事务、分布式一致性。
- 二进制媒体专用优化（本次以文本内容为主）。

## 功能需求

1. 对外暴露文件系统风格 API，支持文件和目录两类节点。
2. 路径解析与规范化能力：
   - 支持绝对/相对路径（具体形式由实现约定）。
   - 防止非法路径跳转（如越级路径）。
3. 文件内容读写：
   - `writeFile` 支持覆盖与创建。
   - `readFile` 返回文本内容。
4. 目录能力：
   - 创建目录、列出目录、递归遍历目录、递归删除目录。
5. 节点操作：
   - 移动、重命名、复制、删除、存在性检查、更新时间刷新。
6. 元数据能力：
   - `stat` 返回节点类型、大小、更新时间等基础信息。
7. 序列化与反序列化：
   - 任意时刻可导出 JSON 友好快照。
   - 可由快照恢复完整 VFS 状态。
8. 压缩策略：
   - 仅文件内容参与压缩。
   - 元数据（路径、文件名、mtime 等）保持明文可读。
   - 支持按阈值压缩（小文本可不压缩，大文本压缩后存储）。

## 非功能需求

- 可维护性：核心层（VFS 语义）与存储层（持久化）解耦。
- 可扩展性：后续可无痛接入 ST 持久化通道与版本管理模块。
- 可靠性：对异常输入和损坏快照有防御性处理（尽可能回退或报错明确）。
- 性能：目录与文件操作在常见规模下保持可接受响应；压缩逻辑不影响基础可用性。
- 兼容性：数据结构严格 JSON 友好，不依赖非序列化类型直接落盘。

## 验收标准

1. 代码中存在并可调用完整扩展档 API（mkdir/list/read/write/delete/exists/move/rename/stat/copy/touch/递归遍历/递归删除）。
2. 能完成端到端流程：创建目录 -> 写文件 -> 读取 -> 重命名/移动 -> 列表查看 -> 导出快照 -> 恢复快照后结果一致。
3. 快照结构可直接 `JSON.stringify` 且可 `JSON.parse` 恢复使用。
4. 元数据字段明文可见，文件内容按策略压缩保存并可正确解压读取。
5. 当前实现不含版本管理相关接口或逻辑；后续可独立增加而不破坏现有 VFS 核心。
6. 至少提供覆盖核心场景的测试或等价验证脚本，证明上述行为成立。

## 风险与待确认项

- 压缩算法选择（deflate/gzip）与实现库依赖需结合当前插件构建链确认。
- 路径规范（分隔符、大小写、根目录约定）需在实现前固定，避免后续兼容成本。
- 大文件或高频写场景下，压缩阈值与性能权衡需要实测校准。
- 后续接入 ST 时，需明确全局配置与会话数据的分层映射规则（本次仅做抽象，不做绑定）。
