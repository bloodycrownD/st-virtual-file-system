# 路径版本库 + 批次稀疏检查点（回滚语义）PRD

## 背景与变更动机

### 原有问题

- 既有实现以 **整棵 `VfsSnapshot` + 变更路径上的 manifest 切片（含「批次前 / 保存前」）** 为主，与中文产品里 **「回滚 = 回到某次提交之后的状态」** 不一致；且 **「仅记录该批次当时 diff 过的路径」** 无法保证「回到较早检查点时，后来新增的路径会被移除」等 **整树 materialization** 语义。
- 用户已明确：**不要「保存前 / 批次前」锚点**；**批次记录与内容快照解耦**；检查点 **只存储当时实际存在的文件与目录（稀疏）**；**重命名按「新路径出现在检查点、旧路径不出现在检查点」统一语义**（等价于创建侧统一，旧路径由「未列出即不存在」隐含删除）。

### 变更目标

1. **语义**：对外统一为 **回滚** —— 将虚拟树 **恢复为某次工具批次或某次保存已成功提交之后** 的物化结果（checkpoint）。  
2. **结构**：**路径级版本链**（内容可 gzip+base64 等）与 **批次（及编辑器提交）检查点** 分离；检查点只持 **稀疏 `path → version` 映射**，不重复内联大块正文。  
3. **取舍**：不再提供依赖「保存前 / 批次前」的 **「撤回到路径不存在」** 能力（用户已接受）。

## 数据模型（产品层约定）

### 1）路径版本库（与批次解耦）

逻辑上为 **按路径索引的版本序列**（持久化形态由 `spec` 定，可为嵌套 map 或等价结构）：

- 每个 **文件** 路径：若干 `{ version, status, content? }`；`content` 为可选编码（如 gzip+base64），**本 PRD 不要求以 MD5 去重**（实现可后加）。
- 每个 **目录** 路径：进表；可无正文，**`status` 区分目录/文件**（或等价字段）。
- **`version`**：在该路径下单调可读的唯一引用（实现可选用递增整数、ULID 等，由 `spec` 定）。

### 2）批次 / 保存检查点（稀疏物化树）

每条检查点（对应一次工具批次成功提交或一次编辑器保存提交）至少包含：

- **`batch` / `checkpointId`**：与执行日志、UI 行可互查的稳定 id。  
- **`tree_version`（稀疏）**：**仅列出在该时刻存在的路径** → 各路径对应的 **`version` 指针**（引用路径版本库中的条目）。  
- **语义规则（核心）**：  
  - **出现在 `tree_version` 中的路径** = 该检查点下 **存在**（文件有对应 `version` 的内容；目录有占位）。  
  - **未出现在 `tree_version` 中的路径** = 在该检查点下 **不存在**（与「当时树上没有该路径」一致）。  
- **父目录链**：**必须完整** —— 若某文件路径在 `tree_version` 中列出，则从 `/` 到该文件父级链上的 **所有目录路径** 也必须出现在同一张稀疏表中（避免「只有叶子、父路径语义悬空」）。

### 3）重命名

不单独建模 `rename` 事件类型：**某检查点的稀疏表即该时刻物化树** —— 新路径出现并指向新版本；旧路径 **不出现在该检查点** → 按规则 **不存在**。与「只把重命名当创建」的表述一致，且与 **「未列出即不存在」** 自洽。

### 4）与 undo/redo 的关系

- 本模型本质是 **基于 checkpoint 的时间旅行**（选择某一检查点并物化）。  
- **Redo** 不是自动自带的；若产品需要 **redo 栈**，须在后续需求中单列（本 PRD 不强制）。

## 范围变更说明（相对原迭代主 PRD / 旧版 feature PRD）

| 维度 | 旧方案倾向 | 本 PRD 定稿 |
|------|------------|-------------|
| 锚点时间 | 批次前 / 保存前 | **仅提交后检查点** |
| 批次与正文 | manifest 子树与批次强耦合 | **解耦**：版本库 + 检查点指针表 |
| 检查点体积 | 单批次 diff 路径可能无法表达「回退整树」 | **稀疏全物化**（当时存在的路径全集 + 父链） |
| 产品用词 | 曾用「撤回」 | **「回滚」** 与 checkpoint 语义一致 |
| 旧持久化 | `tool-batch-pre` / `manual` / `chatVfsSnapshots` | **删除**；读入时剥离，**不**双轨、**不**迁移为检查点 |

**本 PRD 不展开**：具体 JSON 字段名、FIFO/sweep 算法细节 —— 见 **`features/post-only-snapshots-rollback-semantics/spec.md`（破坏性、单轨）**。

## 影响模块与接口（预期）

- **持久化 schema**：`vfs-chat-metadata` **删除** `chatVfsSnapshots` 与 `ChatVfsLogEntry.snapshotId`；新增 `vfsChatPersistenceVersion`、`vfsPathVersionStore`、`vfsCheckpoints`、`checkpointId`；**破坏性读入剥离**（见 `spec.md`）。
- **`ChatVfsRuntime` / 编辑器保存路径**：成功提交后 **仅** 写入检查点 + 版本库；**删除** `buildToolBatchPreRecord` / `persistChatFileSaveWithPreSnapshot` 等 manifest 写入路径。
- **应用管线**：**仅** `applyCheckpointById`（或等价命名）；**删除** `applySnapshotById` manifest 应用逻辑。
- **UI**：`VfsHistoryScreen` 等 **仅** `checkpointId`；Tab / toast 与「回滚」一致。
- **测试**：删除旧 manifest 相关用例，覆盖 v2 与剥离解析。

## 验收标准

1. **检查点稀疏语义**  
   **Given** 检查点 C 的 `tree_version` 仅包含路径集合 S  
   **When** 用户执行回滚到 C  
   **Then** 结果树在 **任意路径 p** 上：若 `p ∈ S` 则与版本库中 `tree_version[p]` 所指内容一致；若 `p ∉ S` 则 **不存在**（含后续曾出现但不在 S 中的路径应被移除）。

2. **父目录链**  
   **Given** 检查点列出某文件路径  
   **When** 校验该检查点数据  
   **Then** 从 `/` 到该文件的所有父目录路径 **均** 出现在同一 `tree_version` 中（或等价强校验失败并拒绝落盘）。

3. **回滚救回删除**  
   **Given** 检查点 C 曾物化包含 `/a.txt`，之后用户手动删除 `/a.txt`  
   **When** 回滚到 C  
   **Then** `/a.txt` **恢复存在**且内容与 C 所指版本一致。

4. **多步创建后回到较早检查点**  
   **Given** 检查点 1 仅有 `/a`（及父链）；检查点 2 有 `/a` 与 `/b`（及父链）；当前树与检查点 2 一致  
   **When** 回滚到检查点 1  
   **Then** `/a` 与检查点 1 一致；**`/b` 不存在**。

5. **编辑器保存**  
   **Given** 用户对某路径保存并产生检查点  
   **When** 回滚到该保存检查点  
   **Then** 该路径物化结果与 **该次保存提交后** 一致（非保存前草稿）。

6. **旧数据（破坏性）**  
   **Given** 元数据中仍存在历史 `tool-batch-pre` / `manual` manifest、`chatVfsSnapshots` 或日志中的 `snapshotId`  
   **When** 用户打开会话并升级到新持久化版本  
   **Then** **不保留**旧还原能力：manifest 与 `snapshotId` **剥离**（见 `spec.md`）；**不得静默损坏** 当前 `chatVfsSnapshot` 文件内容；用户知悉旧「一键还原」历史 **不可用**（发版说明）。

7. **配额与淘汰**  
   **Given** 版本条数或检查点超出配置上限  
   **When** 执行淘汰  
   **Then** 行为可预测（FIFO 或其它在 `spec` 中声明）；**不得**出现仍被某检查点引用却已被静默删除的版本（或必须同步失效检查点，二选一在 spec 写死）。

## 测试用例

| ID | Given | When | Then |
|----|--------|------|------|
| T1 | 检查点仅含 `/a` 及父链 | 回滚到该检查点 | 仅 `/a` 存在且内容正确 |
| T2 | 先后存在检查点 1（仅 a）、2（a+b）；当前为 2 | 回滚到 1 | **`/b` 不存在**，`/a` 与 1 一致 |
| T3 | 检查点含 `/a.txt` 后用户删文件 | 回滚到该检查点 | 文件恢复且内容一致 |
| T4 | 保存产生检查点后继续编辑未保存 | 回滚到该保存检查点 | 与保存提交后一致 |
| T5 | 重命名：`/old` → `/new` 后的检查点 | 回滚到重命名后检查点 | `/new` 存在且内容正确，`/old` 不存在 |
| T6 | 违反父链不完整（构造非法数据） | 落盘或加载 | **拒绝或修复策略**与 spec 一致，不损坏运行 |
| T7 | 旧 metadata 含 manifest / `snapshotId` | 解析升级后 | 无 manifest 应用入口；日志无可用 `checkpointId` 直至新写入；树内容保留 |
