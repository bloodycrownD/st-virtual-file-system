# VFS 历史区：回滚与纵向滚动 PRD

## 背景

在扩展弹窗「执行日志（含工具批次）」区域（`vfs-history-screen`）中，用户需要查阅较长日志并在带快照引用的行上执行回滚。当前反馈存在两类阻塞：**回滚不可用**，以及**缺少纵向滚动**导致无法翻页查看历史记录，影响排错与恢复到批次前安全状态。

## 目标（含成功指标）

- **目标**：历史区在常见日志量下可完整阅读；用户对带快照引用的批次行发起回滚后，虚拟文件系统应恢复到**该批次执行前**的锚点状态，与界面文案「回滚到批次前锚点状态」一致。
- **成功指标（功能向）**：以可测试的验收标准为准（见下文），不额外设定数值型性能指标。

## 用户与场景

- **用户**：使用 VFS 编辑/工具批次的 SillyTavern 扩展使用者（含需要快速撤销一次批量写入、对照执行日志排错的用户）。
- **场景**：
  - 执行多次 `write` 或工具批次后，在历史中定位某条带 `snapshot` 引用的记录并回滚到该批次之前。
  - 日志条目较多时，在同一屏内通过纵向滚动浏览全部记录，无需被裁切。

## 范围

### 包含范围

- **纵向滚动**：历史区主体（执行日志列表/内容容器）在内容超出可视高度时出现稳定纵向滚动，键盘/触控板/滚轮均可浏览完整内容。
- **回滚（全栈）**：从 UI 触发到服务端/扩展内核完成「恢复到该批次执行前锚点状态」的闭环；若当前缺少锚点恢复或接口未接通，纳入本需求补齐。
- **一致性**：回滚成功后，编辑器或 VFS 呈现的状态与「该批次尚未执行」时的锚点一致（以产品可理解的文件树/内容为准）。

### 不包含范围

- 历史区以外的 Tab 或全局导航重构。
- 执行日志的存储结构、保留策略、导出格式等非本缺陷直接相关的能力。
- 性能压测指标、虚拟列表/无限加载等体验增强（除非为实现滚动所必需的最小改动）。

## 核心需求（3–7 条）

1. 历史区在日志高度超过可视区域时，**必须**出现纵向滚动且可滚至首尾。
2. 对标注快照/批次且支持回滚的行，用户触发回滚后，系统**必须**将 VFS 恢复到该批次执行前的锚点状态。
3. 回滚过程中若失败（网络、锚点不存在、版本冲突等），**必须**给出明确错误提示，且**不得**在失败路径上产生未声明的部分写入或状态损坏（与当前状态一致或完整回滚，二选一需在实现层保证其一；验收以「无脏数据」为准）。
4. 回滚进行中应有可感知的进行中状态（避免重复点击）；结束后应反映最新状态（如刷新相关视图或历史列表）。

## 验收标准

### 滚动

- **Given** 执行日志内容总高度大于 `vfs-history-screen` 可视高度  
  **When** 用户将焦点置于历史区并使用滚轮/触控板向下滚动  
  **Then** 可见区域持续下移直至最后一行完全可见，且不出现横向意外溢出（除非单行内容本身需横向滚动，此条不作为本次必测项）。

- **Given** 同上  
  **When** 用户滚动回顶部  
  **Then** 首条日志完整可见。

### 回滚

- **Given** 某行日志对应批次已成功执行且界面提示可回滚到「批次前锚点」  
  **When** 用户对该行执行回滚并确认（若有确认步骤）  
  **Then** 当前 VFS 内容与该批次执行前锚点一致；随后再执行依赖该锚点的读取应得到与回滚前「批次前」一致的结果。

- **Given** 回滚请求因服务端/客户端可识别错误失败  
  **When** 用户查看结果反馈  
  **Then** 展示明确错误原因或错误码对应文案；再次打开相关文件时内容应与回滚前一致（未半更新）。

- **Given** 回滚进行中  
  **When** 用户尝试再次触发同一或其他回滚  
  **Then** 界面阻止重复提交或排队策略明确且不产生重复锚点应用（以不重复应用为准）。
