# VFS 文件快照与回滚（移除提交记录）PRD

## 背景

当前扩展中存在基于聊天级提交记录（如 `chatVfsVersions`）的全局快照式版本能力；用户希望改为 **按路径的快照（manifest）**：快照数据与会话内执行日志 **分离存储**，日志记录操作信息与 **快照引用（版本号）**；并 **移除** 原有的提交记录类能力与对应入口。每条快照记录 **仅包含若干路径在当时的状态切片**（非整棵聊天 VFS 树的重复拷贝），以降低 metadata 膨胀。快照默认 **仅保留最近若干份（默认 10）**。

## 目标（含成功指标）

### 目标

1. 提供 **按路径 manifest 的快照能力**：在 **手动操作** 与 **虚拟工具调用（工具粒度）** 两类触发下生成快照；每条记录仅含 **相关路径在锚定时刻的状态切片**（含路径不存在、重命名涉及的多路径），足以在回滚时 **原子** 恢复这些路径。
2. 提供 **回滚能力**：用户基于执行日志选择一次操作所关联的快照进行回滚；回滚在逻辑上 **原子**：要么整次恢复到快照描述的一致状态，要么 **完全不生效**。
3. **移除** 原有「提交记录」类产品（历史列表、基于旧提交的回滚等），避免两套并行心智模型。

### 成功指标（可验收）

- **功能可用**：手动与工具调用路径均可产生快照；用户可通过日志关联的快照执行回滚；当快照已被淘汰或不可用时，回滚 **明确失败** 且可向用户解释原因（例如快照不存在）。

## 用户与场景

- **作者 / 重度使用者**：在一次工具批量写入后，发现结果不理想，希望 **撤回到本次写入之前** 的快照状态。
- **手动编辑者**：在本地多次手工改动后，希望在执行下一步高风险操作前 **打一个手动快照**，必要时恢复。
- **故障排查者**：通过执行日志对照每次操作关联的快照 id，理解「当时树的状态」与「当前差异」。

## 范围

### 包含范围

- **快照仓库**：存放在 **聊天 metadata** 内（与现有持久化模型一致）；与执行日志 **分离**；日志行记录 **快照版本号 / 快照 id** 等引用关系。单条快照为 **路径 manifest**（多路径时一条记录内包含多条路径条目），**不**要求存整棵 `chatVfsSnapshot` 副本。
- **触发**：**手动** + **工具调用**（一次工具调用视为一条操作粒度，可与现有批次语义对齐）。
- **日志粒度**：与「手动操作」「工具调用」同级；不在本 PRD 内重新定义日志字段细节，但要求日志与快照引用可对齐。
- **结构语义**：快照必须能表达 **删除与重命名** 等带来的状态（不仅是文件字节内容）。
- **保留策略**：**可配置**，**默认保留最近 10 个快照**；淘汰策略可导致旧快照不可用。
- **失败语义**：允许回滚失败（例如快照已清除）；回滚过程 **全部成功或全部失败**，不得在持久化层留下半棵树。

### 不包含范围

- **批量回滚的高级编排**（例如跨多条日志一键撤销多条）：除非明确列为后续迭代，本需求以「单次操作 ↔ 单次快照/回滚」为主。
- **底层存储格式、字段级 schema、迁移脚本细节**：属于后续设计/SPEC，不由本 PRD 展开。
- **执行日志模型的大幅重写**：日志系统 **先保留既有形态**，仅补充与快照引用的衔接需求（具体字段由 SPEC 定义）。

## 核心需求

1. **快照与日志分离**：快照数据独立存放；日志记录操作元数据并 **引用快照版本号**，不把 manifest 正文塞进日志条目。
2. **按路径 manifest**：每条快照记录为 **路径 → 锚定时刻状态** 的条目列表（可含多条路径）；**不**采用「每条快照存整棵聊天 VFS 树」的存储形态（当前权威树仍为 `chatVfsSnapshot`）。
3. **双触发**：手动操作与工具调用成功后均可生成快照（具体触发点以满足「操作粒度」为准）。
4. **单文件与多文件一致**：同一套 manifest 模型既能覆盖单路径（编辑器默认），也能覆盖一次工具批次涉及的 **diff 路径集合**。
5. **状态完备**：manifest 必须能表达 **路径不存在** 与 **存在时的节点内容/结构**（含删除、重命名涉及的多路径）。
6. **保留策略**：默认保留最近 10 个快照；可配置；被淘汰的快照不再可用于回滚。
7. **原子回滚**：回滚在内存中完成校验与组装后再一次性落地；任一步失败则 **整次回滚失败**，不产生中间持久化状态。
8. **移除旧提交体系**：移除提交记录相关能力与入口，避免与快照体系并存。

## 验收标准

### AC-1：快照生成（手动）

**Given** 用户在扩展内执行一次明确的手动快照操作（具体入口由实现定义）  
**When** 操作成功完成  
**Then** metadata 中出现一条新的快照记录（含版本号/快照 id），其 manifest **至少包含**当前编辑器所涉路径的状态切片；对应执行日志（若存在）可关联到该快照引用。

### AC-2：快照生成（工具调用）

**Given** 一次虚拟工具调用批次执行成功并落地到聊天 VFS  
**When** 系统为该次工具粒度记录执行日志  
**Then** 同步存在与该次操作对齐的快照引用（版本号写入日志侧的可判定字段）；快照 manifest **覆盖本次批次所影响的路径集合**在 **批次开始前** 的状态（含「路径不存在」）。

### AC-3：多文件一致性（工具批次）

**Given** 单次工具调用修改了多个路径  
**When** 生成该次操作的快照  
**Then** 该条快照 manifest 所列路径在一次回滚中 **同时** 恢复到该时刻的一致状态（不允许仅恢复其中一部分的定义）。

### AC-4：删除 / 重命名可回滚

**Given** 某次操作包含删除文件或重命名路径  
**When** 用户回滚到该次操作关联的快照  
**Then** manifest 所列路径在树中的存在性与内容与该快照记录一致（包含「路径不存在」「路径存在」、重命名涉及的两条路径等）。

### AC-5：淘汰后回滚失败

**Given** 默认保留策略已淘汰某一快照  
**When** 用户尝试回滚到该快照  
**Then** 回滚失败，并向用户给出可理解的原因（例如快照不可用）；**且** 不产生部分写入的树状态。

### AC-6：原子失败

**Given** 回滚过程中任一校验失败（快照缺失、数据不完整等）  
**When** 结束回滚流程  
**Then** 持久化的聊天 VFS 状态与回滚前保持一致。

### AC-7：移除提交记录能力

**Given** 用户打开扩展相关界面  
**When** 查找旧的「提交记录 / 基于提交的回滚」入口  
**Then** 不应再提供该类入口（若需过渡期，须在里程碑中单独立项，不作为本需求默认验收）。

### AC-8：编辑器页快照入口

**Given** 用户在文件编辑器页  
**When** 执行手动快照或选择回滚到某一快照  
**Then** 写入或恢复 **仅 manifest 所列路径**（默认至少包含当前编辑文件路径）；非 manifest 路径不变；失败时不污染持久化树。若编辑器有未保存缓冲，实现需约定是否先落盘再打快照（SPEC 收口）。

### AC-9：日志屏按行回滚

**Given** 日志屏展示一条带有效 `snapshotId` 的执行日志  
**When** 用户对该行执行回滚  
**Then** 将 manifest **原子应用**后的 `chatVfsSnapshot` 与预期一致；若快照已淘汰则失败且不产生部分写入。

## 界面入口（已定案）

- **文件编辑器页**：提供 **手动快照** 与 **按快照回滚**（面向当前编辑场景；快照体为 **按路径 manifest**，默认覆盖当前文件路径）。
- **日志屏**：展示执行日志；对具备快照引用的日志行提供 **按该条日志回滚**（工具批次等与 `snapshotId` 对齐）。

## 约束与依赖

- 快照与会话绑定，存放在 **聊天 metadata**。
- 执行日志与快照 **分离**；日志侧承载 **快照版本号引用**。
- 保留策略 **默认最近 10 个快照**，且 **可配置**。

## 风险与待确认项

- **metadata 体积**：大文件或多快照仍可能放大聊天记录；保留策略为默认缓解手段，极端场景可能需要后续「体积上限」等非功能增强（不作为本 PRD 默认范围）。
- **旧数据迁移**：是否存在历史提交数据需要迁移或丢弃策略，需在 SPEC/里程碑中单独确认。
