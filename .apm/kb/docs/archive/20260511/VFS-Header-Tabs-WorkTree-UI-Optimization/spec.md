# VFS-Header-Tabs-WorkTree-UI-Optimization 需求说明

## 背景

当前 VFS 弹窗顶部区域存在明显可用性与一致性问题：按钮无法稳定处于同一行；“模板覆盖当前目录”文案过长影响布局；Tab 与普通按钮视觉区分不足；缺少“工作树”Tab 用于直接查看工作树渲染结果。

## 目标

- 统一优化所有 Tab 页面头部区域，确保按钮布局与交互一致。
- 将“模板覆盖当前目录”替换为紧凑 icon 入口，降低头部拥挤度。
- 重构 Tab 样式，提升与普通按钮的可区分性与状态可感知性。
- 新增“工作树”Tab，用于展示 `VIRTUAL_WORK_TREE` 的最终渲染文本。

## 范围

### 包含范围

- 文件管理 / 提交记录 / 日志 / 工作树 四个 Tab 的头部布局统一调整。
- 头部按钮区样式与排列规则调整（单行约束）。
- “模板覆盖当前目录”入口改为 icon + tooltip（tooltip 文案：`覆盖`）。
- Tab 组件样式重做（默认/hover/active 状态）。
- 新增“工作树”Tab 及其页面内容（仅渲染结果文本）。

### 不包含范围

- WorkTree 规则编辑能力（仅展示结果，不支持配置）。
- 文件列表、右键菜单、弹窗主体其他业务逻辑改造。
- 全局主题系统重构或跨插件样式统一。

## 功能需求

1. 顶部按钮区域在桌面端必须保持单行展示，不允许自动换行到第二行。
2. “模板覆盖当前目录”入口替换为单一 icon 按钮，不展示长文案。
3. 该 icon 按钮 hover 时显示 tooltip：`覆盖`。
4. 该 icon 按钮点击后沿用现有覆盖确认流程（行为不变）。
5. Tab 样式需与普通按钮明显区分，至少包含：
   - 更清晰的 Tab 容器边界或背景层；
   - 明确的 active 态视觉（颜色/边框/字重/阴影之一或组合）；
   - 可识别的 hover 态。
6. 新增 `工作树` Tab，切换后显示工作树渲染结果纯文本区域。
7. `工作树` Tab 内容来源为当前上下文对应的 `VIRTUAL_WORK_TREE` 输出结果，不展示调试信息或规则表单。

## 非功能需求

- 样式实现应与当前 VFS 主题风格兼容，不出现突兀对比。
- Tab 切换与按钮点击不应引入可感知卡顿。
- 头部单行布局在常见桌面宽度下稳定可用（无错位/遮挡）。
- 新增 `工作树` Tab 不应破坏已有三个 Tab 的逻辑与状态切换。

## 验收标准

1. 四个 Tab 页面头部按钮区在桌面端均保持单行显示。
2. 文件管理页原“模板覆盖当前目录”长文案已替换为 icon，hover 显示 `覆盖`。
3. Tab 在视觉上可与普通按钮明确区分，active 与 hover 状态均可直观看出。
4. 新增 `工作树` Tab 可正常切换并展示当前 `VIRTUAL_WORK_TREE` 渲染文本。
5. 新增样式与功能不影响原有文件管理、提交记录、日志核心操作流程。

## 风险与待确认项

- “头部强制单行”在极窄宽度下可能导致内容压缩，需要定义最小宽度或降级策略。
- `工作树` 渲染结果较长时的滚动与换行策略需明确（横向滚动 vs 自动换行）。
- Tab 样式增强若过重，可能与宿主主题冲突，需要控制样式权重与作用域。
