# VFS-Display-Strategy-Update 需求说明

## 背景

当前“展示策略”入口位于文件行（row）菜单中，操作路径较深，且在目录上下文中的可发现性不足。与此同时，展示策略弹窗的能力需要与既有工作树渲染规则保持一致，并明确 UI 交互形态，降低配置成本与误操作风险。

## 目标

- 将展示策略入口迁移到 header 菜单，并基于目录层级条件显示。
- 展示策略弹窗能力与既有规则保持一致（排序、读取范围、填充策略）。
- 统一配置控件规范：枚举项使用 `select`，数值项使用“滑块 + 输入框”联动。
- 配置默认值按 spec 初始化，并按作用域（chat/template）持久化。

## 范围

### 包含范围

- 入口位置变更：
  - 展示策略入口从 row 菜单迁移至 header 菜单。
  - 仅当“当前目录不是根目录”时显示该入口。
- 展示策略弹窗功能项（与既有 spec 对齐）：
  - 排序方式：名称 / 创建时间 / 更新时间
  - 排序方向：升序 / 降序
  - 头部读取：0~1000
  - 尾部读取：0~1000
  - 填充策略：文件名 / FrontMatter读取 / 不展示
- UI 控件要求：
  - 可选项（枚举项）统一使用 `select`。
  - 数字项统一使用“滑块 + input”双控件，并保持双向同步。
- 持久化策略：
  - 初始值采用展示策略 spec 约定默认值。
  - 用户修改后按当前作用域（chat/template）持久化。

### 不包含范围

- 不修改工作树渲染核心算法（仅调整入口与配置 UI）。
- 不新增展示策略字段（严格采用现有功能列表）。
- 不调整根目录下其他菜单项展示逻辑（仅针对展示策略入口）。

## 功能需求

1. **入口可见性**
   - 系统判断当前目录是否为根目录。
   - 非根目录：header 菜单显示“展示策略”入口。
   - 根目录：header 菜单不显示“展示策略”入口。
   - row 菜单移除该入口，避免重复入口。

2. **弹窗字段与规则**
   - 弹窗必须包含以下配置项，并保持可编辑：
     - 排序方式（名称/创建时间/更新时间）
     - 排序方向（升序/降序）
     - 头部读取（0~1000）
     - 尾部读取（0~1000）
     - 填充策略（文件名/FrontMatter读取/不展示）
   - 字段值变更后可提交保存到当前作用域配置。

3. **控件交互**
   - `select` 项：
     - 展示当前值。
     - 仅可选择预定义选项。
   - 数值项（头部读取/尾部读取）：
     - 滑块范围固定为 0~1000。
     - 输入框支持直接输入数值。
     - 滑块与输入框实时联动，任一变更同步另一方。
     - 非法输入（非数字、越界）在提交前被约束为有效区间值。

4. **默认值与持久化**
   - 打开展示策略弹窗时：
     - 若当前作用域无用户配置，则加载 spec 默认值。
     - 若已有用户配置，则加载已保存值。
   - 保存后仅影响当前作用域（chat 或 template），不串扰。

## 非功能需求

- **可用性**：控件标签清晰，默认值可见，交互反馈明确。
- **一致性**：字段命名、排序与既有 spec 对齐；UI 组件风格与现有弹窗一致。
- **稳定性**：入口迁移后不影响其他 header/row 菜单功能。
- **兼容性**：在现有 VFS 页面布局中不引入额外滚动或遮挡问题。

## 验收标准

1. 在根目录下，header 菜单不显示“展示策略”入口；进入任一非根目录后显示。
2. row 菜单中不再出现“展示策略”入口。
3. 展示策略弹窗包含且仅包含以下功能项：
   - 排序方式、排序方向、头部读取、尾部读取、填充策略。
4. “排序方式 / 排序方向 / 填充策略”均为 `select` 控件，并可正常切换。
5. “头部读取 / 尾部读取”均为“滑块 + input”组合，且双向联动正常。
6. 数值输入被限制在 0~1000；越界值可被纠正到合法范围。
7. 首次进入作用域时加载默认值；保存后重新打开弹窗可读回已保存值。
8. chat 与 template 作用域配置互不影响。

## 风险与待确认项

- 是否需要在 header 菜单中为“展示策略”提供额外提示文案（如仅目录生效）仍待确认。
- 数值输入越界的处理策略（即时纠正 vs 失焦纠正）当前定义为“提交前约束”，如需更严格即时约束需进一步确认。
- 若未来扩展展示策略字段，需同步更新默认值映射与作用域持久化结构。
