# select-custom-listbox-unification 需求说明

## 背景与变更动机

当前展示策略弹窗中的下拉控件依赖原生 `select`，并同时挂载了 `text_pole` 与局部类名，存在以下问题：

- 样式来源混杂，容易被全局主题规则“二次污染”，导致外框、内边距、字体与同弹窗其他输入项不一致。
- Win + Chromium 下拉展开态主要由系统原生渲染，`option` 样式可控范围有限，视觉上与弹窗主题断层明显。
- 输入框是半透明深色主题，原生下拉展开为平台风格，切换状态时有明显“换组件库”观感。

本次变更目标为“视觉一致性优先”，通过自绘下拉方案实现闭合态与展开态的统一风格。

## 范围变更说明（相对原需求）

相对 `VFS-Display-Strategy-Update` 原需求，本次新增/调整范围如下：

- **新增**：将原生 `select` 升级为自绘 listbox 交互（button + popover/listbox）。
- **扩展**：变更范围从“展示策略弹窗的 3 个 select”提升为“VFS 所有弹窗/表单中的下拉控件”。
- **保持不变**：
  - 字段语义与数据模型不变（排序方式、排序方向、填充策略等值域保持原定义）。
  - 头尾读取数值控件仍为滑块 + input，不在本变更内改形态。
  - 作用域持久化规则（chat/template）不变。

## 影响模块与接口

### 影响模块

- `src/app/components/business-components/VfsActionInputDialog.vue`
  - 需要将 `type: 'select'` 的渲染从原生 `<select>` 切换为自绘 listbox 结构。
- VFS 其他弹窗/表单中存在下拉控件的组件
  - 统一替换为同一套下拉渲染与交互模式（具体文件在设计阶段逐一确认）。
- 相关样式文件（弹窗/表单样式）
  - 增加统一下拉的样式 tokens 与状态样式（默认、hover、focus、open、active、selected、disabled）。

### 接口与契约影响

- 组件对外字段协议保持兼容：
  - 继续使用 `type: 'select'` 与 `options: Array<{ label; value }>`。
  - `confirm` 事件 payload 仍为 `Record<string, string>`，不改变上层业务提交逻辑。
- 新增交互约束（组件内部）：
  - 键盘导航：`ArrowUp/ArrowDown/Enter/Escape/Tab`
  - 可访问性语义：`role="combobox"` / `role="listbox"` / `role="option"` 与 `aria-*` 状态同步。

## 验收标准

1. **统一性**
   - VFS 所有弹窗/表单中的下拉控件均使用同一套自绘 listbox，不再混用原生 `select` 展开态。
   - 闭合态与展开态视觉风格与弹窗输入项一致，不出现平台原生风格跳变。

2. **样式隔离**
   - 下拉组件不再依赖 `text_pole` 作为主样式承载，避免被全局主题规则二次污染。
   - 组件关键样式由独立命名空间类控制，跨主题下保持一致布局与间距。

3. **交互完整性**
   - 鼠标可正常展开、选择、收起。
   - 键盘操作完整：方向键移动、Enter 选择、Escape 关闭、Tab 正常流转焦点。
   - 点击外部区域可关闭弹层，且不影响现有弹窗外部点击逻辑。

4. **数据正确性**
   - 选项变更后，提交 payload 与原原生 `select` 语义一致（`value` 不变）。
   - 展示策略等现有业务分支不需要修改值域解析代码即可正常工作。

5. **回归稳定性**
   - 现有展示策略功能（字段显示、保存、作用域隔离）行为与原验收一致。
   - 现有非下拉输入项（text/range-number）样式与交互不回归。

## 测试用例

1. **组件层（下拉基础行为）**
   - 渲染选中值、展开列表、点击选项后写回值并关闭。
   - 键盘导航与选择行为正确。
   - 外部点击关闭与焦点管理正确。

2. **弹窗集成层（VfsActionInputDialog）**
   - `type: 'select'` 字段使用自绘 listbox；`type: 'text'`/`range-number` 不受影响。
   - 提交 `confirm` 时，返回值与选中项 `value` 一致。

3. **业务回归（展示策略）**
   - 排序方式/方向/填充策略三项均可选择并正确保存。
   - chat/template 作用域隔离与原需求一致。

4. **跨模块一致性**
   - VFS 其他含下拉的弹窗/表单均替换到同一组件实现，视觉与交互一致。
