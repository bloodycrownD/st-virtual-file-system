# VFS-Unified-Viewer-Slideshow-Flow 需求说明

## 背景

当前“文件查看效果”和“文件夹幻灯片”是两套相对独立的进入路径与交互流，用户在查看内容时需要频繁切换模式，操作链路冗长，心智负担较高。

## 目标

- 将“文件查看效果”和“文件夹幻灯片”合并为一个统一的内容查看 UI。
- 以减少模式切换为第一目标，提供一致的顶部操作条与交互路径。
- 保证路由/返回行为可预期：从哪里进入，返回就回到对应来源上下文。

## 范围

### 包含范围

- 文件查看入口与目录幻灯片入口统一接入同一个内容查看界面。
- 统一顶部操作按钮为：返回 / 编辑 / 预览 / Prev / Next。
- `Prev/Next` 翻页规则统一为“当前目录文件序列内翻页”。
- 增加入口来源上下文追踪，用于“从哪进入就从哪返回”。

### 不包含范围

- 不新增自动播放、随机播放、页码跳转、跨目录翻页等高级导航能力。
- 不改动 VFS 存储结构与文件内容序列化逻辑。
- 不做与本次统一 UI 无关的样式重构。

## 功能需求

1. **统一入口**
   - 文件的“查看效果”入口与目录的“幻灯片”入口进入同一套查看界面。
   - 进入统一界面后，顶部栏呈现一致的按钮集合：返回 / 编辑 / 预览 / Prev / Next。

2. **编辑与预览语义**
   - “编辑/预览”指同一文档的源码编辑态（textarea）与渲染预览态切换。
   - 在统一界面中，编辑与预览在同一上下文内可切换，不应触发额外模式跳转成本。

3. **翻页规则**
   - `Prev/Next` 仅在当前目录文件列表中切换前后文件。
   - 边界行为明确：首文件 `Prev` 禁用，末文件 `Next` 禁用。

4. **返回路由规则（核心约束）**
   - 系统需要记录进入统一界面时的“来源上下文”（例如：从文件查看入口进入，或从目录幻灯片入口进入）。
   - 点击“返回”时，必须优先返回进入前的来源上下文，而不是固定返回某个单一页面。
   - 若来源上下文存在且有效，严格按来源返回；（上下文失效策略可在设计阶段补充）。

## 非功能需求

- **一致性**：统一界面的按钮样式、布局、状态反馈保持一致。
- **可预期性**：路由返回行为稳定且可解释，不出现“返回到错误页面/错误目录”的情况。
- **回归安全**：不影响现有保存、预览渲染、目录浏览等核心能力。

## 验收标准

- AC1：文件查看入口与目录幻灯片入口都进入同一查看 UI。
- AC2：统一界面顶部栏包含且仅包含：返回 / 编辑 / 预览 / Prev / Next（可按状态禁用）。
- AC3：`Prev/Next` 仅在当前目录文件中生效，不跨目录、不全局遍历。
- AC4：点击返回时，能回到进入前对应来源上下文（满足“从哪进入就从哪返回”）。
- AC5：编辑/预览切换表现为同一内容上下文内切换，无额外模式跳转干扰。

## 风险与待确认项

- 返回路由的“来源上下文失效”处理策略尚未细化（例如来源实体被删除、目录不可达）。建议在设计方案阶段明确降级路径。
- 统一界面后，按钮密度提高，移动端布局可能需要额外适配规则。
