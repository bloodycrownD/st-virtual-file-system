# action-menu-button-styling 需求说明

## 背景

在 VFS 弹窗的“更多操作”下拉菜单中，菜单项（如“新建目录 / 新建文件”）当前样式异常：

- 视觉与 SillyTavern（ST）原生按钮风格不一致（背景/文字/间距/圆角不协调）。
- 观感像“默认 HTML 按钮”或被错误的主题变量覆盖，导致可读性与一致性下降。

## 目标

- 仅针对 **“更多操作”下拉菜单项按钮** 做样式优化，尽量复用 ST 原生按钮风格（`menu_button`/主题变量）。
- 修复默认态下的可读性与布局一致性（对比度正确、间距与对齐合理）。

## 范围

### 包含范围

- “更多操作”下拉菜单内的所有 `role="menuitem"` 按钮：
  - 新建目录
  - 新建文件
  - 以及后续可能加入的其它菜单项
- 默认状态（default）样式：文字颜色、背景、padding、圆角、宽度/对齐

### 不包含范围

- 不调整 hover/active/focus/disabled 等状态（本次仅 default）。
- 不调整 “更多操作” toggle（summary）本身。
- 不调整 tabs、Up、弹窗标题栏按钮、modal 按钮。

## 功能需求

### FR-1 菜单项视觉对齐 ST 原生

- 菜单项按钮的视觉应尽可能复用 ST 原生（或 `menu_button` 体系）：
  - 字体颜色与背景对比度正常
  - 文字不发灰、不发粉（避免被错误变量影响）
  - 间距/圆角与弹窗其余 `menu_button` 相协调

### FR-2 菜单项布局一致

- 菜单项按钮在下拉菜单中应：
  - 左对齐
  - 宽度一致（建议 `width: 100%`）
  - 行高一致，点击热区合理

## 非功能需求

- **局部作用域**：样式必须限定在 VFS 弹窗作用域内（`#st-vfs-popup`）或组件作用域内，避免污染宿主其它菜单。
- **可维护性**：选择稳定的 selector（例如 `.vfs-action-menu__list button[role="menuitem"]`），减少未来改 DOM 时失效概率。

## 验收标准

- **AC-1 可读性**：菜单项文字颜色与背景对比度正常，清晰可读。
- **AC-2 一致性**：菜单项按钮的 padding/圆角/对齐与 ST `menu_button` 风格接近，不再显得突兀。

## 风险与待确认项

- 不同 ST 主题可能覆盖按钮变量；需要优先使用 ST 现有 CSS 变量并避免硬编码颜色。
