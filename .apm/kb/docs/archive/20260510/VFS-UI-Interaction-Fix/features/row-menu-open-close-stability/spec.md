# row-menu-open-close-stability 需求说明

## 背景

当前行末三点菜单存在开合稳定性问题：

- 多次点击同一三点按钮后，菜单可能不再呼出（状态卡死）。
- 菜单呼出后点击其他区域，菜单不关闭（dismiss 失效）。

这会导致用户误判为交互失灵，影响文件操作效率。

## 目标

- 行菜单支持稳定的重复开合（toggle）。
- 菜单打开时，点击外部区域可可靠关闭。
- 同一时刻仅允许一个行菜单处于打开状态。

## 范围

### 包含范围

- 行末三点菜单（row action menu）的开关状态管理与关闭策略。
- chat + template 两个界面。
- desktop + mobile 两种布局。

### 不包含范围

- 不调整菜单动作集合与业务语义（查看/编辑/重命名/删除等）。
- 不调整 header 三点菜单逻辑。

## 功能需求

### FR-1 重复点击稳定开合

- 点击同一行三点按钮：
  - 第一次打开菜单
  - 再次点击关闭菜单
  - 连续点击不会进入“不可再打开”状态

### FR-2 外部点击关闭

- 菜单打开后，点击菜单外任意区域应关闭菜单。
- 关闭动作不得影响列表滚动位置与当前选中态稳定性。

### FR-3 单菜单互斥

- 任意时刻最多一个行菜单处于打开状态。
- 打开新菜单时，已打开的其它行菜单应自动关闭。

## 非功能需求

- **稳定性**：连续操作（高频点击）下行为可预测。
- **兼容性**：不破坏现有 overlay 定位与滚动不扰动约束。
- **可维护性**：开合状态控制逻辑集中，避免分散在多个层级。

## 验收标准

- **AC-1 多次点击稳定**：同一三点连续点击 10 次，菜单始终可按开/关节奏切换。
- **AC-2 外部关闭可靠**：菜单打开后点击外部区域，菜单必定关闭。
- **AC-3 单菜单互斥**：打开第二个行菜单时，第一个自动关闭。
- **AC-4 双界面一致**：chat/template 下 AC-1~AC-3 均成立。
- **AC-5 回归覆盖**：新增/更新测试覆盖 AC-1~AC-3。

## 风险与待确认项

- 关闭策略需避免误判“菜单内部点击”为外部点击，防止用户点击菜单项时菜单提前关闭。
