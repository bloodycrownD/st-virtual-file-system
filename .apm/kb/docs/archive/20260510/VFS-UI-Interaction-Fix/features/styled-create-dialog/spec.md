# styled-create-dialog 需求说明

## 背景

当前“新建目录/新建文件”使用浏览器原生 `prompt`/`confirm` 交互，存在明显问题：

- 与 SillyTavern（ST）整体 UI 风格不一致（样式突兀、遮挡体验差）。
- 键盘与焦点体验不可控（不同浏览器差异大，且难以对齐 ST 的交互习惯）。

因此需要把“新建”输入改为 **VFS 弹窗内部的风格化 modal**，以保持一致的主题样式与键盘操作体验。

## 目标

- 将“新建目录/新建文件”的输入交互从原生 prompt 替换为 **VFS 弹窗内的自定义 modal**。
- modal 必须符合 ST 风格（按钮、背景、字体、间距与现有 VFS 弹窗一致）。
- modal 必须具备良好键盘体验：打开自动聚焦，Enter 确认，Esc 取消。
- “新建”入口放在 **“更多操作”菜单** 内，且在未选中实体时也可用。
- “更多操作”触发器允许采用**图标化（icon-only）**按钮；语义通过 `title/aria-label="更多操作"` 提供。

## 范围

### 包含范围

- 新增/调整“更多操作”菜单项：
  - `新建目录`
  - `新建文件`
- 新增一个 VFS 内部 modal（目录/文件复用）：
  - 字段：仅名称（目录名/文件名）
  - 操作：确定 / 取消
  - 快捷键：Enter=确定，Esc=取消
  - 自动聚焦输入框
- 新建成功后刷新文件列表，并选中新建项（便于后续操作）。

### 不包含范围

- 不支持输入相对路径（例如 `a/b/c.txt`）——本次只允许“名称”。
- 不支持新建文件的初始内容输入。
- 不改变 VFS 核心能力与协议。

## 功能需求

### FR-1 “更多操作”中提供新建入口（无需选中）

- “更多操作”菜单在未选中实体时仍可展开（至少包含“新建目录/新建文件”）。
- “更多操作”触发器可为 icon-only，不要求可见中文按钮文本；但必须提供 `title` 与 `aria-label`（值为“更多操作”）。
- 当选中实体时，“更多操作”应同时包含原有动作（view/edit/rename/delete 等）与新建入口（可按分组/分隔呈现）。

### FR-2 风格化 modal（VFS 内部）

- modal 在 VFS 弹窗内部显示（不使用浏览器原生 prompt）。
- modal 内容：
  - 标题：`新建目录` 或 `新建文件`
  - 输入框：`名称`
  - 按钮：`确定` / `取消`

### FR-3 键盘与焦点

- modal 打开后输入框自动聚焦。
- Enter：提交（等价点击“确定”）。
- Esc：取消并关闭 modal（不触发新建）。

### FR-4 错误处理

- 名称为空：不提交，并给出用户可见提示（toast 或表单错误）。
- 名称非法/冲突/创建失败：提示失败原因（尽量复用现有错误映射/ toast 文案）。

## 非功能需求

- **一致性**：样式必须跟随 ST/VFS 弹窗主题（暗色背景、边框、按钮 class）。
- **可维护性**：新建 modal 组件应复用（目录/文件共用一套），避免重复逻辑。
- **可访问性**：按钮/输入框具备可聚焦顺序与基本 aria 属性（最小要求）。

## 验收标准

- **AC-1 入口位置**：点击“更多操作”（可为 icon-only 触发器）可看到“新建目录/新建文件”，且在未选中任何条目时也存在。
- **AC-1.1 触发器语义**：当“更多操作”采用 icon-only 时，必须具备 `title/aria-label="更多操作"`。
- **AC-2 不使用原生 prompt**：新建时不会弹出浏览器原生对话框，而是在 VFS 弹窗内显示 modal。
- **AC-3 键盘体验**：
  - 打开 modal 自动聚焦输入框
  - Enter 可确认创建
  - Esc 可取消并关闭
- **AC-4 新建结果**：创建成功后列表出现新条目并自动选中。

## 风险与待确认项

- “更多操作”当前基于 `<details>/<summary>`：需要确认在 ST 的 CSS reset 下同时满足“未选中可展开”与“已选中动作列表”不会产生交互歧义。
