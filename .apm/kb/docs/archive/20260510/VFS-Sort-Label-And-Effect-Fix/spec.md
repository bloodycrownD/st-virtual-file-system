# VFS-Sort-Label-And-Effect-Fix 需求说明

## 背景

当前展示策略中存在两个问题：

- 排序方式选项文案使用“名称”，表达不够明确，期望改为“文件名称”。
- 用户在展示策略中修改排序方式后，文件排序未按预期生效，导致策略配置与实际结果不一致。

## 目标

- 将排序方式相关 UI 文案统一为“文件名称”。
- 修复排序策略应用逻辑，使排序在点击“确定”后生效。
- 保证排序生效同时覆盖：
  - VFS 文件管理列表（UI 立即重排）
  - VIRTUAL_WORK_TREE 渲染输出顺序

## 范围

### 包含范围

- 文案统一：
  - 项目内所有“排序方式=名称”相关 UI 文案改为“文件名称”。
- 排序生效修复：
  - 作用层级：仅当前目录（展示策略弹窗所在目录）。
  - 触发时机：点击“确定”后应用。
  - 生效对象：文件管理列表与 VIRTUAL_WORK_TREE 渲染输出。
- 必要的回归测试补充与调整。

### 不包含范围

- 不变更排序字段语义（仍为 name / ctime / mtime）。
- 不扩展为“当前目录及子目录”或“全局默认排序改写”。
- 不改动排序方向、头尾读取、填充策略的原有业务定义。

## 功能需求

1. **排序方式文案统一**
   - 所有相关 UI 中“名称”选项统一替换为“文件名称”。
   - 文案替换不改变底层值（仍使用 `name`）。

2. **排序应用逻辑（当前目录）**
   - 在展示策略弹窗中修改排序方式并点击“确定”后，当前目录排序策略立即生效。
   - 当前目录文件列表按新规则重新排序，无需重新进入目录或重开弹窗。

3. **渲染输出一致性**
   - VIRTUAL_WORK_TREE 输出顺序与当前目录已应用的排序规则一致。
   - UI 列表排序与渲染输出排序保持一致（同一排序字段/方向下）。

4. **作用域约束**
   - 仅更新当前目录对应策略，不影响其他目录。
   - 若其他目录有独立策略，保持原行为不变。

## 非功能需求

- **一致性**：UI 文案、列表排序、渲染输出三者语义一致。
- **即时反馈**：点击“确定”后用户可立刻在当前界面观察到排序变化。
- **稳定性**：不引入菜单、弹窗、列表滚动等已修复交互回归。
- **可维护性**：排序逻辑应集中在既有策略应用链路，避免 UI 与渲染出现双轨实现。

## 验收标准

1. 展示策略弹窗中排序方式显示为“文件名称 / 创建时间 / 更新时间”。
2. 项目内所有相关“排序方式=名称”文案统一为“文件名称”。
3. 当前目录修改排序方式并点击“确定”后，文件管理列表立即按新排序显示。
4. 同次修改后，VIRTUAL_WORK_TREE 输出顺序与新排序一致。
5. 排序影响仅限当前目录；其他目录排序不受影响。
6. 无需刷新页面、切换目录或重开弹窗即可观察到当前目录排序结果。

## 风险与待确认项

- 需确认“项目内所有相关 UI 文案”覆盖边界（是否包含历史文档快照中的静态示例文案）。
- 当目录内存在“目录 + 文件”混排时，需明确“目录优先”规则是否继续高于排序字段（当前预期保持原规则）。
- 若当前目录策略与全局默认策略冲突，需保证优先级仍遵循既有设计（目录覆盖优先）。
