# YAML 展示优化与正文字数统计 PRD

## 背景

当前故事/文稿视图中，顶部 YAML（或同类元数据）区域字号偏大、层次弱，与正文对比显得突兀；右下角仅有创建/更新时间，缺少对正文篇幅的直观反馈。

## 目标（含成功指标）

- **体验目标**：元数据区视觉克制、层次清晰，与正文区分明显但不抢戏；用户无需滚动或切换即可在右下角看到当前正文的字符规模。
- **成功指标（可观察）**：
  - 元数据区在典型分辨率下不再出现「标题级」大号强调样式主导首屏的情况（以设计走查通过为准）。
  - 字数/字符统计与创建、更新时间同处右下角，文案与顺序一致、无遮挡。

## 用户与场景

- **用户**：使用本扩展阅读或编辑带前置元数据的文稿（含中文创作场景）的 SillyTavern 用户。
- **场景**：打开某篇文稿，快速扫一眼时间/环境等元信息，同时需要知道正文大概多长（用于篇幅控制或心理预期）。

## 范围

### 包含范围

- 顶部 YAML/元数据**展示样式**优化：字号、颜色、间距、键值可读性、与正文的区块分隔（如轻量底栏/卡片/分隔线等，具体实现不在本 PRD 约束）。
- 右下角在「创建」「更新」信息旁增加**正文字符统计**，统计口径见验收标准。
- **不**对 YAML 键名做纠正、重命名或迁移（键名保持数据原样，仅优化 UI）。

### 不包含范围

- 修改存储格式、批量迁移历史文件键名。
- 多语言分词意义上的「词数」、英文按单词计数（除非后续单独需求）。
- 全文检索、导出、版本对比等与本视图展示无关的能力。

## 核心需求（3–7 条）

1. 元数据区采用与正文明显区分且克制的排版（键、值在视觉上可区分，例如字重/颜色/字号层级之一或组合）。
2. 长文本类元数据（如摘要）在首屏占用可控，避免与正文同级的「大块标题感」（可通过折叠、行数上限+展开、或更小字号等任一符合体验的方式达成）。
3. 较短字段在空间允许时可考虑并排展示以节省纵向空间（可选，不作为唯一方案约束）。
4. 右下角展示**正文**字符统计，与创建、更新时间共同呈现，布局稳定、小屏下不严重换行错乱。
5. 字符统计**不**纳入顶部 YAML/元数据区内容，仅针对正文主体。

## 验收标准

1. **Given** 文稿含顶部 YAML 与多段正文 **When** 打开该文稿视图 **Then** 元数据区与正文在视觉上分为两个层次（背景/边框/间距或字号层级至少一种），且元数据区整体不比正文更「抢眼」（走查：默认首屏以正文阅读为主）。
2. **Given** 元数据中存在较长多行值 **When** 查看首屏 **Then** 该区域可通过更小字号、折叠或「展开」等机制控制占用，用户仍能访问完整内容。
3. **Given** 任意 YAML 键名（含非常规拼写） **When** 渲染元数据 **Then** 不因键名字面内容做数据层改写；界面仅做展示样式优化。
4. **Given** 固定正文样本（含中文、标点、空格与换行）**When** 查看右下角统计 **Then** 显示数值等于该正文字符串长度（**含**空格、换行、标点），且**不含**顶部 YAML/元数据区文本。
5. **Given** 用户编辑正文（若视图可编辑）**When** 内容变化 **Then** 右下角字符统计在合理延迟内与当前正文一致（实时或失焦更新均可，需在实现侧择一，但不得长期 stale）。
6. **Given** 窄窗口宽度 **When** 查看页脚 **Then** 创建、更新与字符统计仍可读，不出现互相覆盖或不可见（允许换行，但信息完整）。
