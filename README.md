# 虚拟文件系统（SillyTavern 扩展）

在 SillyTavern 里装了这个扩展之后，你会多出一套**只存在于当前聊天里的虚拟文件**：像网盘一样建文件夹、写 `.md` 或 `.txt`，路径和真实硬盘无关。写提示词或角色卡时，往往用宏把其中一部分内容**塞进发给模型的上下文**——本 README 要说的 **工作树** 和 **目录规则**，就是决定「**哪些虚拟文件会进这条宏、以什么形式出现**」的两层机制。

---

## 工作树：发给模型的「入选名单」

可以把它想成一份**入选名单**：名单上的文件，才会进入工作树相关的宏输出（例如整段工作树文本）；不在名单上的，宏里就当它们不存在。

- **只针对文件，不针对文件夹。** 文件夹不会在名单里单独占一行；有结果的是「某个文件进不进名单」。
- 文件列表里那颗**小灯**，照字面理解就行：**亮 = 进名单**，**灭 = 不进名单**。它和宏里实际出现的情况是一致的，不会出现「灯灭了宏里还有」或反过来。
- 默认情况下，新文件**不会**自动帮你选成「必进」或「必不进」；多数文件会先走下面说的「听所在文件夹的安排」——也就是默认跟父目录走。

如果你从不点任何开关、也不配规则，可以简单记：**工作树 = 当前聊天里，最终会参与「工作树宏」的那批虚拟文件及其形态**。

---

## 目录规则：每个文件夹怎么「安排自己的孩子」

每个**文件夹**（界面里的一行目录）可以帮你做两件事，容易混在一起，分开记会清楚很多：

### 1）开关：「这个文件夹要不要管孩子？」（非根目录才有「关掉」）

在**根目录以外的文件夹**上，往往有一个类似「规则·开 / 关」的开关（文案以你界面为准）。它只表达一件事：

- **开**：这个文件夹**愿意**对自己**直接放在里面的文件**（下一层文件，不包括孙子文件夹里的文件）套用自己配的「怎么排序、取前几段、怎么写进正文」等设置。
- **关**：这个文件夹**不管**。此时，那些**选择「听父目录安排」**的文件，**不会**进工作树（灯灭），直到你把开关打开，或者你单独给文件改成「必须进」或「必须不进」（见下一节）。

**根目录（最顶上那一层 `/`）没有「关掉不管」这种选项**——根目录永远在「管」的语义上；你能改的是「具体怎么管」（排序、头几条、尾几条等），不能整层关掉「根下面不听规则」。

### 2）配置：「具体怎么管？」——排序、头批、尾批、正文里写什么

点进某个文件夹的「目录规则」「纳入规则」或类似入口（以界面为准），配的是**数学意义上的处理规则**，例如：

- 子文件**按名字还是时间排序**；
- **从头数几条、从尾数几条**进上下文（常见用途：一个目录里很多笔记，只把最新的几条塞进模型）；
- 正文里是**只出现文件名**、还是**带一段正文 / 头信息**等。

这些配置**只对满足下面两个条件的文件生效**：

1. 文件就在这个文件夹的**下一层**（直接子文件，不自动往上找爷爷文件夹的规则）；  
2. 这个文件**没有**被你设成「必须进」或「必须不进」，而是**选择听父目录**（默认往往是这一种）。

**一句话**：目录规则 = 「在这个文件夹里，对**听话的那批直接子文件**，按我配的顺序和条数，决定进不进工作树、进了以后长什么样」。

## 每个文件上的三种态度（和文件夹开关谁说了算）

每个文件（不是文件夹）大致有三种态度，界面上可能是图标或菜单循环切换：

1. **必须进**  
   不管父文件夹开关关没关、规则会不会把它排掉，**都进工作树**，灯亮。一般按**全文**进上下文（以你当前版本行为为准）。

2. **必须不进**  
   优先级最高：就算父文件夹开着规则、规则本来会把它选进来，**也一律不进**，灯灭。

3. **听父目录的**（多数文件的默认）  
   只看**紧挨着的上一层文件夹**（直接父目录）：  
   - 父文件夹**开了**上面的开关 → 按该文件夹里配好的「排序、头尾、正文形态」算进不进、怎么进；  
   - 父文件夹**关了**开关（且父目录**不是根**那种「不能关」的情况）→ **不进**工作树；  
   - 父目录是根 → 根永远在「会管」的一侧，具体按根上配的那套规则来。

**不会**出现「子文件去合并爷爷、祖爷爷文件夹的规则」这种自动往上串的逻辑；**永远只看这一层的爸爸文件夹**。

记优先级可以只记一句：**「必须不进」压一切，「必须进」压文件夹规则，剩下才轮到「听父目录」和目录里那套排序/条数。**

---

## 和「虚拟文件」本身的关系

虚拟文件系统负责**存文件、改路径、编辑内容**；工作树和目录规则负责**在「要把虚拟世界塞进模型」时，筛谁、怎么排版**。你可以有很多文件在磁盘树里，但只有进了工作树的那份名单，才会按你设定的方式出现在宏里。

## 开发者

仓库用 Vue 3 + TypeScript + Vite 构建；扩展入口为 `src/main.ts`，构建产物为 `dist/index.js`（见 `manifest.json`）。

**预览全屏（移动端）**：文件预览顶栏提供「全屏」时，依赖浏览器的 **Fullscreen API**（对预览内容区 `requestFullscreen`）。部分环境（尤其 **iOS / 移动 Safari**）对「非视频元素」全屏支持不完整或不可用；此时按钮会禁用或通过提示说明，属浏览器能力限制而非扩展逻辑错误。

```bash
npm install
npm run build
npm test -- --run
```
