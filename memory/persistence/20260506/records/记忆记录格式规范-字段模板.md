## 背景

需要一个“可检索、可合并、可追溯”的统一记忆记录格式，方便后续把关键知识/结论/决策沉淀到 `memory/`，并支持未来的程序化处理（导入/导出/去重/回填等）。

## 结论 / 事实

- 记忆记录建议具备最小必填字段：`id/title/content/scope/subject/tags/source/confidence/created_at/updated_at`。
- 推荐字段用于生命周期与冲突管理：`kind/status/expires_at/importance/conflicts_with/supersedes/notes`。
- `subject` 与 `source` 的结构化约定用于避免串记、支持追溯复核。
- 模板提供 JSON 与 YAML 两套，便于手写与程序生成。

# 记忆记录（Memory Records）格式规范

目标：把“对话里需要长期/短期保留的信息”用**可检索、可合并、可追溯**的统一格式落地，便于后续自动化处理（例如导入/导出、去重合并、按范围回填提示词等）。

---

## 1. 一条记忆记录的最小集合（必填）

每条记录建议都具备以下字段（字段名固定，值允许为空但字段应存在）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一 ID。推荐：`mem_<yyyymmdd>_<rand>` 或 `mem_<timestamp_ms>` |
| `title` | string | 1 句话概括，便于列表浏览/检索 |
| `content` | string | 具体记忆内容（尽量客观、可复用，避免对话口癖） |
| `scope` | `"global" \| "character" \| "chat" \| "group"` | 作用域（决定“回填”到哪里） |
| `subject` | object | 记忆的主体标识（见下文模板） |
| `tags` | string[] | 标签（用于筛选/聚类/冲突检测） |
| `source` | object | 来源（消息索引、时间、是谁说的等，可追溯） |
| `confidence` | number | 0~1 置信度（主观判断：越接近 1 越可信） |
| `created_at` | string | ISO 时间：`YYYY-MM-DDTHH:mm:ss.sssZ` |
| `updated_at` | string | ISO 时间 |

---

## 2. 推荐字段（强烈建议）

| 字段 | 类型 | 说明 |
|---|---|---|
| `kind` | `"fact" \| "preference" \| "plan" \| "relationship" \| "profile" \| "rule" \| "summary" \| "other"` | 记忆类型 |
| `status` | `"active" \| "deprecated" \| "contradicted"` | 是否仍有效 |
| `expires_at` | string \| null | 过期时间（短期记忆/临时约定可用） |
| `importance` | 1\|2\|3\|4\|5 | 重要度（用于优先回填/裁剪） |
| `conflicts_with` | string[] | 记录与哪些 `id` 冲突（人工或程序生成） |
| `supersedes` | string[] | 当前记录替代了哪些旧记录（去重合并用） |
| `notes` | string | 仅给维护者看的备注，不参与回填 |

---

## 3. `subject`（主体）约定

`subject` 用于精确定位“这条记忆属于谁/哪里”，避免只靠自然语言导致串记。

### 3.1 推荐结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | `"user" \| "assistant" \| "character" \| "chat" \| "group" \| "system"` | 主体类型 |
| `id` | string | 主体唯一标识（例如 characterId/chatId/groupId） |
| `name` | string | 展示名（便于人读） |

### 3.2 示例

```json
{
  "type": "character",
  "id": "char_42",
  "name": "某个角色"
}
```

---

## 4. `source`（来源）约定

`source` 用于追溯这条记忆从哪里来，便于复核与清理。

### 4.1 推荐结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `channel` | `"chat"` \| `"import"` \| `"manual"` \| `"system"` | 来源渠道 |
| `chat_id` | string \| null | 对应聊天 ID（若有） |
| `message_id` | string \| number \| null | 对应消息 ID/索引（若有） |
| `speaker` | `"user" \| "assistant" \| "character" \| "system" \| "unknown"` | 谁提供的信息 |
| `evidence` | string \| null | 可选：原文摘录/关键句（短） |

---

## 5. 建议的书写规则（让后续更好用）

- **内容要“可复用”**：尽量写成可在其他回合直接引用的事实/偏好/规则，而不是当下语境里的省略句。
- **一条记录只表达一个核心点**：后续合并/失效更清晰。
- **有冲突就显式标注**：用 `status="contradicted"` + `conflicts_with=["mem_xxx"]`。
- **能过期就设置过期**：短期约定（“这次只用中文回答”）不要污染长期记忆，写 `expires_at`。
- **标签风格固定**：推荐用小写与短横线，例如 `diet-vegetarian`、`timezone-utc8`。

---

## 6. 可复制模板

### 6.1 JSON（单条）

```json
{
  "id": "mem_20260506_001",
  "title": "",
  "content": "",
  "kind": "fact",
  "scope": "chat",
  "subject": { "type": "chat", "id": "", "name": "" },
  "tags": [],
  "status": "active",
  "importance": 3,
  "confidence": 0.7,
  "source": {
    "channel": "chat",
    "chat_id": null,
    "message_id": null,
    "speaker": "unknown",
    "evidence": null
  },
  "conflicts_with": [],
  "supersedes": [],
  "notes": "",
  "created_at": "2026-05-06T00:00:00.000Z",
  "updated_at": "2026-05-06T00:00:00.000Z",
  "expires_at": null
}
```

### 6.2 YAML（更适合手写）

```yaml
id: mem_20260506_001
title: ""
content: ""
kind: fact
scope: chat
subject:
  type: chat
  id: ""
  name: ""
tags: []
status: active
importance: 3
confidence: 0.7
source:
  channel: chat
  chat_id: null
  message_id: null
  speaker: unknown
  evidence: null
conflicts_with: []
supersedes: []
notes: ""
created_at: 2026-05-06T00:00:00.000Z
updated_at: 2026-05-06T00:00:00.000Z
expires_at: null
```

## 7. 文件组织建议（放在 `docs` 里怎么存）

- `docs/memory-records.md`：**规范与模板**（本文件）
